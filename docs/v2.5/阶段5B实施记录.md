# v2.5 阶段 5B 实施记录

> 状态：5B-1 至 5B-5 已实现，真实 Compose 工程门禁全绿；阶段 5 工程关闭
> 更新日期：2026-08-06
> 前置：阶段 4 已由真实 Compose CI 关闭；阶段 5A 版本化定义与受控公式已实现

## 1. 阶段目标

把 5A 已生成的版本化领域定义接入标准 MCP Resource `list/read`，并保证发现和读取都由
Host 签名的 subject/project 上下文授权。内部共享服务 token 只认证服务连接，不能替代最终
用户身份，也不能通过 URI 参数让模型选择项目或租户。

5B-2 在这个只读 Resource 基线上继续把定义版本、公式编译结果、数据 Invocation、数据
Evidence 与最终 Claim 串成可复核链路；历史报告必须读取生成时绑定的定义版本，不能按当前
有效版本重新解释旧结论。

## 2. 5B-1 实际交付

- 增加传输无关的 Resource descriptor、文本内容和 provider 契约；Tool 与 Resource 继续共用
  同一个官方 MCP SDK Server，但只有 `knowledge-tools` 声明 Resource capability；
- `resources/list` 与 `resources/read` 都解析并校验 Host RequestContext 签名。SDK 1.28 的
  `read_resource` 高层客户端方法不接收 `_meta`，客户端适配层改为构造同一标准
  `ReadResourceRequest`，显式携带签名上下文；
- `knowledge-tools` 在服务端校验 project、conversation 与 subject 成员关系，只列出签名项目
  内可见定义。读取继续使用 opaque `chatbi://domain-definitions/{id}`，跨项目、未知主体、
  错误对话和未知 URI 均返回不可发现语义；
- Resource descriptor 固定定义 ID、语义键、版本和公式 hash；JSON 内容包含可复核的公式、
  粒度、scope、来源和生效区间，不返回 tenant、创建主体、幂等键或数据库内部字段；
- Resource wire metadata 固定 `chatbi-mcp-resource-v1`，客户端发现契约漂移时失败关闭；
  Resource 业务错误使用稳定 `com.chatbi/error-code` 返回，不泄漏意外异常正文。

## 3. 5B-2 实际交付

- `domain_definition_lookup` 成功解析时，把 definition ID/version、semantic key、公式 hash、
  opaque Resource URI、来源和编译后 Tool 参数 hash 固化到定义 Evidence；
- Agent 在数据 Tool 执行前按 canonical 参数 hash 匹配当前 Run 已解析的编译调用。精确匹配
  才把定义绑定写入策略审计和数据 Evidence；同一 Tool 参数被模型改写或同时匹配多个定义版本
  时失败关闭，不产生未绑定的数据结果；
- 数值 Claim 自动同时引用数据 Evidence 与定义 Evidence，并写入 `definition_execution`
  value ref。Verifier 对 Resource 六元组、Evidence 关联和数据调用逐项复核，缺失或漂移不能
  通过最终交付；
- 新增项目成员隔离的
  `GET /projects/{project_id}/domain-definitions/reports/{report_id}/lineage`。复核从报告
  Artifact 的 `analysis_ids` 反查数据 Artifact/Invocation/Evidence、定义 Evidence、Claim 和
  不可变 `domain_definitions` 记录；歧义、跨 Run 绑定、定义漂移或 Claim 缺失均返回
  `degraded`，无适用定义链路返回 `not_applicable`；
- 新定义版本发布后，旧报告仍按原 definition ID/version/hash 复核，不使用当前 effective
  winner 覆盖历史口径。本切片复用既有 Evidence/Claim/Artifact 真相表，无需新增 schema。

## 5. 5B-3 实际交付

- Resource wire contract 升级为 `chatbi-mcp-resource-v2`。新增项目绑定的稳定目录 Resource
  `chatbi://domain-definitions/catalog/{project_id}`；目录包含可见定义 ID、semantic key、
  version、formula hash 与 opaque URI，不暴露 tenant、创建主体或幂等字段；
- `resources/list` 改为真实分页：服务端固定页大小，响应携带 `nextCursor` 与完整授权目录的
  `catalog-version`。游标由服务端签名，绑定 subject/project/conversation、契约版本、目录版本
  和 offset；同一对话断线后更换 Run 可继续，篡改、跨对话复用或目录漂移均失败关闭；
- 官方 SDK 的 `resources/subscribe`/`unsubscribe` 已接入签名 Host `_meta`，Server capability
  正确声明 `subscribe=true`、`listChanged=true`。订阅快照同时固定目录 hash 和内容 hash，
  后台只读轮询发现变化后发送标准 `notifications/resources/list_changed` 与
  `notifications/resources/updated`，通知 metadata 带前后目录版本并由 Client 校验；
- 领域定义版本 Resource 继续不可变。发布 v2 只更新项目目录并产生目录变更；旧 v1 URI 与
  内容 hash 不变。订阅目录 Resource 才表达“项目新增了定义版本”，不把旧版本伪装成原地修改；
- Resource page/list/read/subscribe/unsubscribe/notification 已通过规范 Client Gateway 暴露；
  进程内兼容传输可做同步 list/read/订阅授权检查，但明确不伪造异步通知。

## 7. 5B-4 实际交付

- 原有 MCP 传输探针扩展为 `chatbi-mcp-transport-probe-v2`：同一个可变、项目/主体隔离
  Resource 真相源同时经 stdio 和 stateful Streamable HTTP 执行签名分页、跨 Run 游标恢复、
  `read`、订阅、版本化 `list_changed`/`updated` 通知、退订静默和跨项目失败关闭；两条传输的
  Resource 内容 hash、初始目录版本及发布后目录版本必须完全相同；
- SDK 服务的页大小与订阅轮询周期增加显式运行时配置。生产默认值保持 50 条/1 秒，E2E
  profile 固定 2 条/0.25 秒，使真实分页和通知无需依赖超大夹具或不稳定等待；
- `ManagedMCPClientGateway` 保存 subject/project/conversation/URI 绑定的订阅意图。Resource
  只读操作遇到裸 SDK 会话错误或连接中断时执行有界重连；新连接必须先重新完成 Tool 目录
  校验，再用原签名上下文恢复订阅。签名、授权、游标和目录漂移等稳定协议错误不参与重试；
- 新增容器内 `apps.api.mcp_resource_reconnect_probe`：在共享 SQLite 中发布隔离定义夹具，
  对真实 `knowledge-tools` HTTP 服务和同镜像 stdio 服务做分页/read 等价比较，订阅项目目录后
  由 Compose 门禁重启 `knowledge-tools`，确认连接代次增加、自动重新订阅，并在新定义发布后
  收到两类标准通知；报告写入既有 `.data/e2e` CI 工件目录。

## 9. 5B-5 实际交付

- 新增持久 `SourceDocumentStore`：原文以不可变 UTF-8 blob 保存，原子 manifest 绑定稳定
  source、document ID 和内容 hash；`KB_DOCS_DIR` 降为受信导入/首次种子目录，API 内联文本也
  进入 `KB_SOURCE_DIR`，默认重建不再误删内联原文；
- 原文先发布、索引后构建。embedding 或索引发布失败时当前活动索引继续服务，原文事实源
  保留待下一次 full rebuild 收敛；删除同样先更新事实源，派生索引可由重建修复；
- Local JSON 存储从单文件升级为不可变 `generations/index-*.json` + 原子 `active.json`
  指针，支持 active/previous 双向回滚、至少保留两代的清理，以及只读 `knowledge-tools`
  跨进程跟随 API 切代；`index.json` 只保留为兼容镜像；
- `kb_admin` Local/Milvus Lite 离线备份升级为 manifest v2，同时校验/恢复原文及相应索引
  状态，明确排除可重建模型缓存；旧 format 1 Local 备份仍可恢复，恢复时会移除不兼容的
  新活动指针；
- 根 Compose 将原文、索引、知识备份和模型缓存拆成四个命名卷；新增共用 Milvus 拓扑与
  CPU/GPU 覆盖文件，二者复用 BGE 模型、集合和 Tool/Resource 契约，仅 device/GPU 资源声明
  不同；`RAG_RUNTIME_PROFILE` 对 baseline/cpu/gpu 后端组合失败关闭；
- Dockerfile 新增显式 `api-rag` 重依赖 target，默认 `api` 构建仍只安装轻量 `rag-store`；
  `knowledge-tools` 已移除只能使用 Local 的旧限制，可连接 profile 内 Milvus。
