## 本批目标

阶段 4 先建立服务端可信协作边界，再接入执行器，最后实现 React 交互。4A-1 建立计划
修订与审批原语；4A-2 把同一授权事实接入 Executor、MCP Client Gateway 和 MCP Server。
本阶段不把浏览器按钮视为授权，也不启用新的高风险工具；目标是让计划干预和审批成为
可持久化、可恢复、可审计、失败关闭的控制面事实。

## 已完成

### SQLite v7 协作控制面

- 新增 `approval_records`，把授权固定绑定到 tenant、project、subject、run、活动计划版本、
  逻辑步骤、工具名、工具 schema hash、参数摘要 hash、风险等级和有效期；
- 新增 `approval_operations`，记录审批决定和一次性消费的幂等操作、结果版本及 TaskEvent；
- ApprovalRecord 绑定字段由 SQLite trigger 保持不可变，状态只允许
  `pending / approved / denied / consumed / revoked`；
- v6→v7 升级先生成带来源 hash 的数据库备份；v7 checksum 已纳入启动校验、readiness、
  工作区备份、恢复校验和迁移演练；
- ApprovalRecord 不保存原始工具参数，只保存规范化 schema 与参数摘要的 SHA-256。

### 用户计划修订

- 新增 `POST /agent/runs/{run_id}/plan/revisions`；
- 只允许在 `paused` 且没有 `running/unknown` 工具调用的安全边界修改；
- 使用 `If-Match` 和 `Idempotency-Key` 防止并发覆盖及重复创建；
- 每次成功修改生成不可变 TaskPlan 新版本、`plan.revised` 事件和 Checkpoint，任务不会自动
  恢复；
- 修订必须通过现有 TaskPlan 契约，不得扩张当前计划以外的 capability；已完成或已跳过
  步骤不得删除或改写，显式跳过会持久化为 `skipped`。

### 高风险审批

- Agent Host 可在 `paused` 安全边界创建 ApprovalRecord；仅接受 `high/critical`，
  有效期不得超过 24 小时；
- 新增 `GET /agent/runs/{run_id}/approvals`，只返回绑定当前 tenant/subject 的安全摘要；
- 新增 `POST /agent/runs/{run_id}/approvals/{approval_id}/decision`，只有固定 subject
  可以批准或拒绝，且同时校验 TaskRun 与 ApprovalRecord 版本；
- 审批决定后任务保持 `paused`，必须显式恢复；
- Gateway/Executor 可通过内部消费接口一次性消费批准记录；消费时再次比对 subject、
  当前计划版本、工具名、schema hash、参数摘要 hash 和有效期，任一漂移均拒绝。

### 4A-2 审批执行链

- Executor 从与 MCP `tools/list` 相同的 Tool Capability Contract 读取风险等级；只有
  `high/critical` 进入审批链，未知或未绑定当前 ready 计划步骤的高风险调用失败关闭；
- 高风险调用在创建 ToolInvocation 和发出 MCP `tools/call` 前，原子创建
  ApprovalRecord、把 TaskRun 从 `running` 转为 `paused`、追加 `approval.requested`
  事件并写入 Checkpoint；等待授权不会消耗工具调用次数；
- 存在有效 `pending` 授权时，恢复 API 返回 `409`，防止项目成员通过普通 resume 绕过
  审批；批准或拒绝后仍需显式恢复；
- Agent Host 恢复后按 tenant、subject、run、活动计划版本、逻辑步骤、工具、契约 hash
  和参数 hash 重新定位授权。只有未过期的 `approved` 记录可在执行前原子转为
  `consumed`，拒绝、撤销、过期、已消费或任一绑定漂移均不会执行工具；
- 已消费的授权 ID、版本、契约 hash 和参数 hash 进入 Host 所有的 MCP RequestContext。
  部署传输继续对完整上下文做 HMAC 签名，浏览器和模型均不能生成该凭据；
- Managed MCP Client Gateway 在连接和调用传输前校验授权；MCP Server Adapter 在输入
  schema 校验后、调用 handler 前再次校验。两个边界都要求当前工具契约和规范化参数与
  授权完全一致，并返回稳定的 `approval_required` 错误；
- 新增 `AGENT_APPROVAL_TTL_SECONDS`，默认 900 秒，配置范围 60–86400 秒；
- 当前生产目录没有 `high/critical` 工具，本批只完成可验证的安全执行链，不改变现有工具
  风险等级或生产能力集合。

## 安全与一致性结论

1. Web 只读取和决定后端 ApprovalRecord，不能自行产生有效授权。
2. 计划、参数、工具契约或主体发生变化时，旧批准不能被消费。
3. 请求、决定、消费均有幂等重放保护；同一幂等键绑定不同请求时失败关闭。
4. 所有成功控制操作同时推进 TaskRun 状态版本、追加 TaskEvent 并更新快照；暂停边界生成
   Checkpoint。
5. 计划修订和审批均不会隐式恢复任务，避免浏览器重试触发执行。
6. 已批准记录先被一次性消费，再创建 ToolInvocation；消费后进程崩溃会要求重新授权，
   不会在授权状态不确定时执行。
7. Gateway 与 Server 都从单源 Tool Contract 计算契约 hash，并对当前规范化参数重新计算
   hash；传输重连不能放宽授权条件。
