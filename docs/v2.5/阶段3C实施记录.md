# v2.5 阶段 3C 实施记录

> 状态：已完成；提交 `e3d51fd` 的后端、前端与 Docker/Compose CI 全绿
> 更新日期：2026-07-31

## 1. 当前实现

### Host 解析器

- `packages/session/coref.py` 从 SQLite 真相源构建当前对话 Artifact 和当前项目 Dataset
  目录，不调用模型；
- 支持第一/第二等序号、最近图表/报告/表格/数据集、唯一文件名，以及显式
  `analysis_id`/`dataset_ref`；
- “这个图”等多候选引用进入结构化阻塞澄清，序号越界不再回退到最后一张图；
- 显式澄清 ID 可以消除原始泛指，伪造或其他项目 ID 不会进入目标集合。

### 持久化与执行约束

- 解析结果以 `HOST_COREF_V1` 绑定进入 TaskContract/TaskPlan；
- 绑定使用不超过 Planner assumption 上限的紧凑 kind/目标 ID 和 resolution hash，不保存
  用户原始提及；分析 ID、类型和数据集血缘在恢复时从 SQLite 重新构建；
- Checkpoint 恢复重新验证主体、项目、对话、目标存在性和 hash；
- Agent 的 `meta` 与结构化日志公开解析状态/hash，模糊或未解析状态不开放工具；
- `generate_report` 使用绑定 Artifact 的 `analysis_ids`，`gen_chart` 使用绑定目标的唯一
  `dataset_ref`，可以覆盖模型给出的错误同项目血缘。

### 安全与审计

- 跨 tenant、项目/对话不匹配、删除目标和篡改 hash 均失败关闭；
- 审计不记录用户查询、凭据样例、Artifact payload 或 Dataset profile；
- 修复 governance audit 对 session 包的反向依赖，避免从 `audit` 首次导入时形成循环。

### 已确认实体映射

- `packages/session/memory_refs.py` 冻结 `memory-reference-v1` 契约；只接受
  `user_confirmation` 来源的 `entity_mapping`、`field_alias` 和
  `confirmed_decision`，普通自然语言记忆仍只是模型上下文；
- 映射由不泄露别名的稳定 semantic key、严格 JSON 摘要和唯一项目内资源 Link 组成；
  `field_alias` 只能指向 Dataset，其他两类只能指向当前对话 Artifact 或当前项目 Dataset；
- 解析先读取 TaskRun 固定 MemorySnapshot，再用治理只读查询检查 live 状态、版本、
  有效期、置信度、内容 hash、冲突和目标归属；任何漂移都失败关闭；
- 同名或冲突映射进入阻塞澄清。用户显式选择 `memory_id` 只对当前 run 生效，
  `HOST_MEMORY_REF_V1` 保存版本、绑定 hash 和冲突选择标记，Checkpoint 恢复保持同一目标；
- Agent 只把 Host 验证后的最小 ID/字段注解交给 Planner/Executor；Replanner 必须原样
  继承 Host 假设，`gen_chart`/`generate_report` 服从已验证血缘；
- 澄清、解析和恢复路径均不写 Memory Repository；长期记忆查看、纠正、删除由后续 3D
  独立实现，未反向放宽 3C 的解析边界。

### 质量与恢复门禁

- `scripts/coref_quality_eval_set.jsonl` 冻结 23 个领域中立场景，同时运行
  `ReferenceResolver` 与 `MemoryReferenceResolver`；覆盖序号、最近对象、唯一/重复
  文件名、多候选、显式 ID、删除、过期、冲突、版本漂移和跨项目/对话攻击；
- `scripts/coref_quality_eval.py` 输出集合 hash、确定解析率、误绑定率、应澄清召回率和
  跨项目泄漏数；报告不保存查询、别名、Memory 正文或资源 ID，CI 强制执行并上传；
- `scripts/mcp_transport_probe.py` 先通过 Host 对象引用和 MemorySnapshot 映射同一个
  Dataset，把相同作用域和快照 ID 注入 MCP RequestContext，再比较直接调用、stdio 与
  Streamable HTTP 的结果 hash、协议协商和错误码；
- `memory_recovery_probe.py` 现在创建真实 `memory-reference-v1` 确认映射，并把
  `HOST_COREF_V1`/`HOST_MEMORY_REF_V1` 写入 probe TaskPlan；
- `run_compose_e2e.sh` 在 probe 建立后重启 API 并验证一次，再执行离线备份、破坏和恢复；
  两次都校验 plan ID/version/hash、固定 compaction/snapshot、两个 resolution hash、
  目标 Artifact、报告副作用恰好一次和 probe 工具调用为零。
