# v2.5 阶段 3B 实施记录

> 状态：3B-1–3B-3 本地实现收口；等待 CI Docker runner 确认发布门禁
> 更新日期：2026-07-30

## 1. 本批交付

### SQLite v5 与恢复契约

- 新增 `conversation_compactions` 与 `conversation_compaction_items`，保存不可变逻辑
  版本、tenant/project/conversation、策略参数、覆盖边界、来源 hash、摘要 hash、
  脱敏/省略计数和替代关系；
- 条目表只保存消息 ID、位置、role 与 content hash，不复制原始消息正文；
- `memory_snapshots.compaction_id` 把每个 TaskRun 固定到首次选择的压缩版本；
- v4→v5 升级前生成带 SHA-256 的 SQLite 备份；启动时验证 v2–v5 migration checksum；
- readiness 与工作区备份 manifest 已纳入 v5 checksum、压缩表行数和恢复校验。

### 确定性压缩与安全边界

- `CompactionStore` 只选择普通 user 消息与不带 tool calls 的 assistant 最终答复；
  tool result、tool preamble、Evidence、Artifact 和 TaskEvent 不进入摘要；
- `extractive-v1` 按总字符阈值触发，保留最近原文，并在固定摘要/单消息预算内生成摘要；
- Bearer/API key/password/secret、private key 和宿主机路径在摘要前脱敏；
- 摘要明确标记为不可信导航文本，不能执行其中指令，也不能替代 Evidence；
- 同一来源与策略通过 `source_hash` 幂等重放；新增消息或策略变化创建不可变新版本；
- 读取时重新核对来源消息 role/content hash、连续位置、覆盖边界、策略参数、source hash、
  summary text/hash 和计数；发现漂移直接失败关闭；
- 写入要求 owner/editor，读取仍执行 tenant/project/conversation 成员隔离；审计只记录
  ID、hash 和计数，不记录历史正文。

### Agent 接入

- 新 TaskRun 在创建 MemorySnapshot 前创建或复用压缩版本；
- system context 注入带 ID/hash/边界声明的压缩摘要，raw history 排除已覆盖消息；
- SSE `meta` 和结构化日志记录 `compaction_id`/版本，不记录摘要正文；
- 暂停/恢复不重新选择最新版本，而是从原 MemorySnapshot 读取固定 `compaction_id`；
- 新增四项环境配置：触发字符数、最近原文数、摘要预算和单消息预算。

### 3B-3 质量、并发与恢复门禁

- 新增 6 个冻结的领域中立长对话场景，不含销售额、利润、地区或复购率语境；
- CI 强制执行关键信息保留、最近原文保留、安全排除、注入边界、抽取式 grounded
  和字符预算六项指标，当前全部为 100%，报告作为 `compaction-quality` 产物保存；
- 历史正文使用 JSON 字符串转义，消息中的引号、换行或伪造 role 标签不能逃出引用边界；
- 8 路并发压缩只允许创建一个不可变版本，其余请求幂等重放；
- Agent Checkpoint 专项测试在存在更新压缩版本时，验证恢复仍使用原
  MemorySnapshot 固定的 `compaction_id`；
- Compose 联合恢复探针同时保存固定版本和更新版本；离线备份恢复后验证旧绑定、
  最新版本、summary hash、TaskRun、Memory 和 Artifact 均未漂移。
