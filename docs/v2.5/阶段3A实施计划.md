# v2.5 阶段 3A：记忆契约、持久化与安全边界

> 状态：实现已收口；3A-1–3A-4 已落地，待 Docker runner 实际执行恢复门禁
> 更新日期：2026-07-30
> 范围：领域无关的记忆控制面；不包含自动摘要、指代消解 UI、领域语义层

## 1. 目标

阶段 3A 为后续上下文压缩、指代消解和项目记忆建立可信底座。交付后，Host 可以在一次
TaskRun 开始前生成不可变的记忆快照，并能证明每条记忆的来源、项目、作用域、版本和
有效性；模型和 MCP Server 不能直接写入或枚举完整项目记忆。

本批必须保持以下边界：

1. 记忆用于上下文导航，不是数值或统计 Evidence；
2. 所有读写先经过当前认证主体和项目成员权限；
3. 长期记忆写入由 Host 的 `MemoryPolicy` 决定，不提供通用 `memory.write` Tool；
4. MCP Observation 只保存 Server/Tool/版本、Invocation、结果 hash、受控引用和允许摘要；
5. 删除、过期、冲突或跨项目的记忆不得进入新快照；
6. TaskRun 固定使用创建时的 `memory_snapshot_id`，运行中记忆变化不静默改变上下文；
7. SQLite 单写入者原则不变，不为“记忆服务”增加第二个数据库写入进程。

## 2. 不在本批范围

- `compaction.py` 的模型/规则摘要实现；
- `coref.py` 的“第二张图”“上次口径”等指代消解；
- 面向用户的记忆管理页面；
- 版本化领域指标、公式编译和知识 Resource；
- 自主假设扩张、并行分析、多数据集 Join；
- 受限 SQL、Code Interpreter、外部 MCP 或多实例状态。

上述能力分别属于 3B–3E、阶段 4–6或独立安全项目，不能借 3A 绕过评审。

## 3. 数据契约

### 3.1 MemoryRecord

每条受控记忆至少记录：

- 不透明 `memory_id`、`tenant_id`、`project_id`；
- `scope`：conversation / project / subject；
- `kind`：字段别名、用户偏好、已确认决策、实体映射或受控摘要；
- 允许进入模型上下文的有界 `content_summary`；
- `source_type`、`source_ref`、`source_hash`；
- `confidence`、`valid_from`、`expires_at`；
- 逻辑 `version`、`status` 和替代/冲突引用；
- 创建主体、创建时间、修订时间和删除时间。

`content_summary` 不保存凭据、宿主路径、原始数据行、完整工具结果或未脱敏文件正文。
身份和项目字段由 Host 从认证上下文注入，不能由模型参数提供。

### 3.2 MemorySnapshot

快照至少记录：

- 不透明 `memory_snapshot_id`；
- tenant/project/subject/conversation/run；
- Memory Policy 版本和选择条件 hash；
- 创建时间、所含记录数量和稳定内容 hash。

快照条目保存 `memory_id + memory_version`，并冻结当时的有界 `MemoryRecord` 副本，避免
软删除或状态修订改变运行中 TaskRun 已读取的上下文。该副本只能包含已通过 Memory Policy
的摘要和血缘元数据，不复制原始消息、完整工具结果、数据行或文件正文。已开始的 TaskRun
继续读取自己的快照；删除操作会阻止新快照引用，历史快照仅用于当前任务恢复和审计。

### 3.3 MemoryLink

关联只允许指向当前项目已经登记的 Conversation、TaskRun、Dataset、Analysis、Artifact、
Claim、Evidence 或 Invocation。Repository 必须校验目标存在、项目一致和版本可用，
不能接受模型提交的任意路径或外部 URI。

## 4. 组件责任

| 组件 | 责任 |
|---|---|
| Memory Repository | 事务化创建、修订、软删除、按作用域查询、快照和关联校验 |
| Memory Policy | 来源准入、作用域、置信度、有效期、冲突、敏感内容和上下文预算 |
| Context Builder | 只读取指定快照的有界摘要；明确标记为 memory，而不是 Evidence |
| Evidence Validator | 拒绝用 MemoryRecord/summary 代替数值、Artifact 或知识来源 |
| Audit/Event | 记录创建、修订、冲突、删除、快照和拒绝原因，不记录敏感正文 |
| MCP Gateway | 只发送 `memory_snapshot_id` 和执行所需引用；Server 无权枚举记忆 |

## 5. 实施批次

### 3A-1：schema 与迁移

状态：**已实现**。

- 增加 MemoryRecord、MemorySnapshot、快照条目和 MemoryLink 的正式表及索引；
- 升级 schema 版本，提供 checksum、重复迁移、故障回滚和旧数据库兼容测试；
- tenant/project/作用域和逻辑版本使用数据库约束，候选外键删除语义显式化；
- 迁移演练只操作隔离副本，不接触活动 `.data/chatbi.db`。

### 3A-2：Repository 与 Memory Policy

状态：**已实现**。

- 实现内部类型、Repository 和事务 API；
- 写入必须附带受信 source，修订使用乐观版本；
- 相同语义键但内容冲突时形成 conflict，不采用“最后写入覆盖”；
- 过期、删除、低置信或越权记录不进入检索结果；
- 写入、修订和删除使用幂等键，恢复或重试不产生重复记忆。

### 3A-3：快照与上下文边界

状态：**已实现**。

- TaskRun 创建/恢复时生成或恢复 `memory_snapshot_id`；
- RequestContext 增加 `memory_snapshot_id` 和 `evidence_ledger_version`；
- Context Builder 按预算选择摘要并保留来源引用；
- Verifier 明确拒绝把 memory reference 当数值 Evidence；
- MCP RequestContext 只包含 ID/版本，不包含完整项目记忆。

### 3A-4：恢复与容器门禁

状态：**已实现；Docker runner 执行结果待本批提交后确认**。

- `workspace_admin` 在写服务停止后统一备份 SQLite、Dataset 和 Artifact，manifest
  显式记录 schema、migration checksum、表行数、文件大小与 SHA-256；知识库继续由
  `kb_admin` / `milvus-backup` 独立管理；
- 恢复前完整校验备份，要求 `--service-stopped --yes --replace-files`，并保留
  `pre-restore-*` 覆盖前副本；
- readiness 校验 SQLite `quick_check`、当前 schema、v4 checksum 和 Memory 控制面表，
  失败时返回 503，不以空库继续；
- Compose E2E 创建 non-empty MemorySnapshot 与 paused TaskRun，停止所有写服务后备份，
  主动移走 SQLite/报告文件，再恢复并验证原 TaskRun、快照 hash、Artifact 文件和副作用
  计数；
- 恢复不重写快照，也不重复调用已经有确定结果的工具；CI 容器任务直接执行该门禁。

## 6. 必测矩阵

| 类别 | 最低验收 |
|---|---|
| 项目隔离 | 项目 A 的记录、快照 ID 和关联在项目 B 下全部拒绝 |
| 身份边界 | 请求体伪造 subject/tenant 不能改变 Host 注入的认证主体 |
| 来源 | 无 source、非法 source_ref、跨项目 Evidence/Artifact 均拒绝 |
| 冲突 | 同一语义键的不同值进入 conflict，不静默覆盖 |
| 生命周期 | 过期、软删除和被替代记录不进入新快照 |
| 幂等/并发 | 同幂等键重试只产生一条记录；版本冲突稳定失败 |
| Evidence | Memory 摘要不能满足数值、Artifact 或知识来源门禁 |
| 快照稳定性 | TaskRun 执行中新增记忆不改变已有快照 hash |
| 恢复 | 重启后恢复相同快照和未完成任务，不重复工具副作用 |
| 传输 | 宿主机、stdio、Streamable HTTP 使用相同引用和拒绝语义 |
| 隐私 | trace、事件和 MCP payload 不出现凭据、原始行或宿主路径 |

## 7. 验收与退出条件

3A 只有在以下条件全部满足后才能进入 3B：

- schema 升级、重复迁移、故障回滚和隔离恢复全绿；
- Memory Repository/Policy 的项目、主体、来源、冲突、删除和幂等测试全绿；
- Memory 无法替代 Evidence 的负向测试全绿；
- TaskRun 快照固定，恢复后不重复工具调用；
- stdio 与 Streamable HTTP 的引用边界一致；
- Compose 重建恢复在 Docker runner 通过；
- 文档、schema、API 类型和审计字段一致，没有把 3B–3E 能力提前标为完成。

## 8. 回滚

- 3A 上线前备份旧 schema 数据库并记录 hash；
- 新表和新字段在旧代码读取路径中保持可忽略，避免破坏 v2.4 任务查询；
- 只允许在没有活动 TaskRun 时执行回滚；
- 回滚不删除 Dataset、Artifact、Evidence 或历史 TaskEvent；
- 若 Memory 初始化或迁移失败，服务 fail-closed 并报告 readiness，不使用空记忆库伪装成功。
