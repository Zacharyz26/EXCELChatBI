# v2.5 阶段 4C 实施记录

> 状态：已完成；提交 `2f2771f` 的恢复、浏览器与 Docker/Compose CI 全绿
> 更新日期：2026-08-03

## 1. 本阶段目标

阶段 4C 负责把 4B 的浏览器会话内协作界面提升为服务端事实源上的可恢复控制面：

- SSE 断线后按持久事件游标续接并抑制重复事件；
- 页面刷新或新浏览器不依赖 `sessionStorage` 找回最近 TaskRun；
- Web/API/工具服务重启后，计划、Evidence、Artifact 和报告仍保持一致；
- 前端展示实际 MCP 来源、版本、风险、权限和执行时健康，但不连接 MCP；
- 浏览器入口明确拒绝 `/mcp`，并以 Compose 浏览器流程验证代理和恢复边界。

## 2. 实际交付

### 2.1 服务端恢复契约

- `TaskStore` 增加按 `conversation_id` 查询最近 TaskRun，复用现有
  `conversation_id/created_at` 索引，不新增迁移；
- 新增 `GET /agent/runs/by-conversation/{conversation_id}/latest`，先执行对话访问检查，
  无权限主体仍统一得到 `404`；
- 新增只读 `GET /agent/runs/{run_id}/stream`：支持 `Last-Event-ID: <run_id>:<sequence>`
  或 `after_sequence`，冲突、负数和跨 Run 游标均以 `400` 拒绝；
- 重连时先订阅活动 producer，再回放数据库 TaskEvent，以 sequence 拼接并去重，避免查询
  窗口内丢事件；终态 Run 返回持久事件和 `done`，不会重放控制写请求；
- `RunManager.subscribe()` 只建立被动订阅，不会把暂停、澄清等待或取消状态误改为运行中。

### 2.2 浏览器恢复与重复抑制

- 工作区选择项目或对话时从服务端查询最近 Run；浏览器缓存仅保留兼容记录，不再作为恢复
  事实源，清空缓存或更换浏览器仍能找回任务；
- SSE parser 读取标准 `id:` 字段。客户端同时按 `event_id` 和 TaskEvent `sequence` 去重，
  拒绝混入其他 `run_id` 的事件；
- 初始 POST 流在终态前结束时，客户端携带最后游标切换到只读 GET 重连，并使用有界退避；
  恢复、澄清和单步重试的 POST 不会因网络故障被自动重放；
- 刷新 TaskRun 时从服务端快照的 `last_sequence` 读取最近事件窗口，长 Run 的待澄清状态
  不再受首个 1000 条事件限制。

### 2.3 工具与 Evidence 审计一致性

- Agent 工具注册表从实际 MCP descriptor 和路由生成可展示契约摘要，包括 service、tool、
  version、risk、required permissions、只读/幂等声明和 contract hash；
- `step.started` 持久策略事件保存调用前契约与权限快照；成功 Evidence 另外保存实际 transport、
  Gateway health/generation、降级状态和同一契约摘要；
- TaskRun 详情用持久 Invocation、策略事件和 Evidence 生成 `tool_audits`。前端展示服务、工具、
  版本、风险、权限、执行时健康及 Evidence/Artifact 引用；缺失健康时明确显示“未记录”，
  不以当前服务存活状态伪造历史执行状态；
- 审计投影沿用 Run 项目访问检查，浏览器不读取 Server 私有 `_meta` 或凭据。

### 2.4 Web 代理与 Compose 门禁实现

- Nginx 显式转发 `Last-Event-ID`，继续关闭 SSE buffering/cache；
- Web edge 对 `/mcp` 和 `/mcp/` 显式返回 `404`；
- Compose 脚本在初始报告流程后重启 `web`、`api` 和 `report-tools`，先验证原 Run 的报告
  副作用只有一次，再以全新 Chromium 会话恢复 TaskRun、工具审计卡和 PDF；
- 恢复浏览器同时验证公开 `/mcp/` 为 `404`。原有离线备份/恢复和固定记忆/血缘引用探针
  继续在同一脚本中执行。
