## 1. 本阶段目标

本节是 4B 当时的目标与来源约定；下文 ApprovalRecord 仅属于已撤下审批流程，不是当前仍开放的事实源接口。

阶段 4B 把 4A 已完成的 TaskRun、不可变计划修订、结构化澄清、运行控制和
ApprovalRecord 接入现有 React 对话工作区。前端只负责展示和提交用户决定，服务端
TaskRun 状态、`If-Match` 版本与 ApprovalRecord 始终是可信事实源。

本阶段不实现 SSE 游标重连、API/Compose 重启恢复和自主等级；这些仍属于后续 4C/4D。

## 2. 实际交付

以下列表记录 4B 当时交付。当前 [`client.ts`](../../apps/web/src/api/client.ts) 与 [`workspace.ts`](../../apps/web/src/stores/workspace.ts) 仍消费 TaskRun、计划修订、澄清和运行控制；ApprovalRecord 类型、审批请求及卡片已随 `7a3d03a` 撤下，不能按本节恢复它们。

### 2.1 类型化 API 与流式续跑

- 为 TaskRun、TaskPlan/TaskStep、TaskEvent、ApprovalRecord 和阻塞澄清增加前端类型；
- 接入任务详情、事件、审批列表、暂停、取消、计划修订和审批决定 API；
- 以 `fetch` 统一消费聊天、恢复、澄清回答和单步重试的 POST SSE，兼容 CRLF、分块边界
  与多行 `data`；
- 所有控制写操作发送服务端要求的 `If-Match` 和 `Idempotency-Key`；
- `/chat/stream` 可在响应头到达时读取 `X-ChatBI-Run-ID`，也能从 v2 TaskEvent 恢复
  当前 run。

### 2.2 工作区状态

- Zustand 工作区保存当前对话最近一次 TaskRun、计划/步骤、审批和待回答澄清；
- 发送消息、恢复、回答澄清和单步重试后统一刷新对话、Artifact、Dataset 与 TaskRun；
- 对话切换后按会话级 `sessionStorage` 恢复最近 run，读取失败时清除陈旧引用；
- 状态变化来自服务端详情或 TaskEvent；前端不会把本地按钮状态当成授权；
- 持久化会话快照落地后立即清除临时流式卡片，避免 TaskRun 刷新期间正文或 Artifact
  重复渲染。

### 2.3 统一任务协作面板

本节中高风险审批展示、“批准一次／拒绝”及批准后继续是历史 UI，不是当前操作步骤；TaskRun、澄清、暂停／恢复／取消、计划和重试部分仍按现行服务端契约工作。

工作区标题栏新增“任务协作”入口和等待处理提示。面板集中提供：

- TaskRun 状态、状态版本、计划版本、目标和终态原因；
- 安全边界内的暂停、显式恢复和取消；
- 结构化澄清答案提交，并在同一个 `run_id` 上续跑；
- 暂停态完整计划编辑、步骤目的修改和步骤跳过；保存后显示不可变新版本；
- 失败/阻塞步骤的单步重试；
- 高风险审批的风险、工具、计划/步骤、有效期、工具契约 hash 和参数摘要 hash；
- 带原因的批准一次或拒绝。批准只更新 ApprovalRecord，任务仍保持暂停，必须再次
  显式点击“继续执行”。

面板已适配窄屏；浏览器不连接 MCP endpoint，也不持有 MCP 服务凭据。
