# v2.5 阶段 3E：完整血缘与恢复

> 状态：3E-1–3E-3 本地实现完成；等待提交后的 CI/Compose 门禁
> 更新日期：2026-07-31
> 前置条件：3A–3C 已关闭；3D 本地实现完成并与本批一起等待 CI；v2.4 G7 继续
> `review_required`

## 1. 目标

用现有 SQLite 真相表贯通项目内的
`Dataset → Analysis/ToolInvocation → Artifact → Evidence → Claim`，让项目成员能查看
“数据从哪里来、经过什么执行、形成什么工件和证据、支持哪些结论”，并在删除 Dataset、
API 重启、工作区备份和离线恢复后保持相同来源证明。

3E 不建立第二套可写图数据库，不把血缘写入 Memory Repository，也不开放通用
`memory.write`、任意 SQL、计划编辑、审批或任务恢复前端。Analysis v1 节点以
`invocation_id` 为稳定身份；逻辑 `analysis_id` 仅作为安全元数据。

## 2. 安全与一致性不变量

1. Dataset、Artifact、Invocation、Evidence 和 Claim 的现有 SQLite 行仍是唯一业务真相；
2. Dataset 删除只保留项目、名称、父引用、创建/删除时间等最小 tombstone，不保留画像、
   变换正文或文件内容；
3. Dataset 父引用与 Artifact 数据集引用一经形成不可改写，Dataset 显示名可受控同步；
4. 图查询必须通过 tenant/project membership；conversation 筛选只保留该对话直接引用的
   Dataset 及其祖先；
5. API 不返回工具参数、文件路径、数据样本、Artifact payload、变换或结果正文；
6. 越权项目和对话统一按不存在处理；审计只记录图 hash、计数、完整性和拒绝原因类型；
7. 图由确定性排序和规范序列化生成 hash；重复读取、数据库重开和恢复必须保持相同 hash；
8. 跨 run Claim/Evidence、跨项目 Invocation/Artifact、Artifact/Dataset、Dataset 父链和
   锚点漂移都会使 readiness、备份或恢复失败关闭；
9. 图响应有 `max_nodes` 上限；`graph_hash`、总节点数和总关系数始终描述完整图，
   `truncated` 明确标记有界视图；
10. 工作区备份必须包含 TaskPlan/Step、Claim/Evidence、不可变 Dataset 锚点的行数与
    非正文血缘内容 hash。

## 3. 实施批次

### 3E-1：SQLite v6 与安全血缘 API

状态：本地实现完成。

- schema v6 新增 `dataset_lineage_anchors`，并为 Dataset 父引用和 Artifact 数据集引用增加
  不可变快照列；
- insert/delete/rename 与表级防改写触发器保留最小 Dataset tombstone；
- `LineageStore` 从现有外键和安全元数据派生五类节点、七类关系、确定性图 hash 与完整性问题；
- `GET /projects/{project_id}/lineage` 提供项目或 conversation 级有界只读图；
- readiness 验证 v6 checksum 和全库血缘完整性。

### 3E-2：前端查看与领域中立质量门禁

状态：本地实现完成。

- 对话工作区标题栏新增“数据血缘”入口；
- 抽屉按数据集、分析执行、分析工件、证据、结论五阶段展示状态、入/出关系和安全详情；
- 删除 Dataset 显示为 tombstone，详情明确不返回参数、路径、样本或结果正文；
- 6 个冻结领域中立场景覆盖 profile、完整 Claim 链、删除派生链、项目隔离、有界视图和
  锚点漂移；
- CI 强制六项指标 100%，并上传 `lineage-quality` JSON 报告，报告不包含资源 ID 或正文。

### 3E-3：备份、重启和恢复

状态：本地实现完成；真实 Compose runner 待提交后确认。

- 工作区 manifest 增加 v6 checksum、锚点/Plan/Claim 行数和非正文 lineage hash；
- API 重启与离线破坏/恢复探针固定项目 `graph_hash`、节点数和关系数；
- 恢复后同时验证 TaskRun、MemorySnapshot、ConversationCompaction、TaskPlan、Artifact、
  Host 引用绑定、工具副作用次数和完整血缘图；
- full-stack Playwright 在真实 Web/API 完成记忆治理、Excel 上传和血缘查看；
- Compose runner 延续单写入者、停写备份、覆盖前 quarantine 和精确文件恢复约束。

## 4. 退出条件

- 完整五类节点和来源关系可由项目成员安全查看；
- 删除父/子 Dataset 后来源链仍存在，画像和文件正文不会进入 tombstone；
- 跨 tenant/project/conversation 不泄露节点，conversation 视图不混入无关 Dataset；
- 锚点、跨 run 或跨项目漂移使 readiness/备份失败关闭；
- v3/v4/v5 数据库可备份迁移至 v6，重复打开 hash 稳定；
- 领域中立质量门禁、Ruff、strict mypy、完整后端、前端 lint/build、普通和真实
  full-stack E2E 通过；
- 提交后的 backend、frontend、lineage-quality 和 Compose browser/recovery CI 全绿后，
  才能关闭阶段 3 并进入阶段 4。

## 5. 3E 之后

3E 的真实容器门禁关闭后进入 **阶段 4：人机协作与 Agent 前端**。第一批应冻结计划查看/
编辑、结构化澄清、暂停/继续/取消、Evidence/风险展示和 ApprovalRecord 的服务端授权边界；
不得把前端按钮当作授权，也不得让浏览器直连 MCP Server。
