# v2.5 阶段 3D 实施记录

> 状态：3D-1–3D-3 本地实现完成；等待提交后的 CI/Compose 门禁
> 更新日期：2026-07-31

## 1. 本批交付

### Repository 与治理契约

- `MemoryStore.list_records_for_governance()` 在未指定 conversation 时返回项目内全部
  主体可见的 conversation/project/subject 生命周期记录；指定 conversation 时继续严格
  限定该对话；
- `revise()` 继续创建不可变 active 新版本、supersede 旧 active/冲突版本，并在同一事务
  中复制旧版本的资源 Link；
- 现有 owner/editor 写权限、viewer 只读、subject 可见性、版本冲突、幂等请求 hash、
  软删除和无正文审计契约保持不变；
- 没有新增 schema 迁移，也没有伪造聊天消息作为纠正来源。新版本保留原始来源，
  治理 actor、请求 hash、幂等键和替代链由操作表及审计证明。

### FastAPI

- 新增项目记忆列表、详情、纠正和删除路由；
- 列表支持 lifecycle/status/scope/kind/conversation 筛选和有界分页；
- 对外响应只包含治理所需字段和项目内受控 Link，不暴露 tenant、subject、scope key、
  semantic key、来源引用/hash 或创建主体；
- PATCH 只接受 `content_summary`、`confidence`、`expires_at` 和 `expected_version`；
- PATCH/DELETE 强制 `Idempotency-Key`，越权按 `404`、并发/幂等冲突按 `409`、
  Policy/参数拒绝按 `422` 返回。

### React

- 对话工作区标题栏新增“项目记忆”入口；
- 新面板支持全部生命周期展示、状态/作用域筛选、刷新、纠正和软删除；
- 纠正表单只开放摘要、置信度和有效期，明确保存产生新版本；
- 删除确认明确不会改写历史快照；
- 前端请求统一复用 Bearer-aware API client，并为每次写操作生成独立幂等键。

### E2E

- full-stack fixture 在隔离数据库中预置一条 `user_confirmation` 来源的项目记忆；
- Playwright 经真实 Web/API 查看该记忆、纠正为 v2、验证旧版本保留，再软删除 v2；
- 原 Excel 上传和 SQLite/parquet 主流程继续在同一测试中执行。

## 3. 当前边界与发布门禁

- 本机没有 Docker，尚未执行根 Compose 的真实镜像重建与容器恢复链路；
- 3D 没有开放自动长期记忆提取或通用 `memory.write`；
- 3D 没有实现恢复已删除记忆；当前删除是可审计软删除，恢复策略需产品决策后另行设计；
- 3D 没有加入成员管理、OIDC/OAuth 或企业审计后端；
- 计划编辑、高风险 ApprovalRecord、暂停/恢复前端和自主等级仍属于阶段 4。

经负责人授权，3E 已在等待 3D 发布门禁期间条件性完成本地实现。提交并推送后必须检查
backend、frontend、coref/compaction/lineage 质量、MCP transport 和 Compose
browser/recovery jobs。全部真实 CI 通过后才能分别关闭 3D 和 3E。
