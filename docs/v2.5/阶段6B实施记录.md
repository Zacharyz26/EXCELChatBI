# 阶段 6B 实施记录：数据角色与质量建议

> 状态：6B-1～6B-4 本地实现完成；双传输/Compose 恢复门禁已接入，等待完整 CI
> 更新日期：2026-08-11
> 前置：阶段 6A 已由提交 `b67b704` 的完整 CI 关闭

## 1. 切片目标

阶段 6B 在 6A 的不可变 capability/tool 目录、数据版本、共享预算和 Evidence Ledger 上，
先交付不读取模型猜测、不修改数据的数据角色与质量建议能力。6B-1 只回答三件事：字段最可能
属于什么角色、依据和不确定性是什么、当前画像支持哪些清洗建议；不自动执行填补、删除、去重
或 Join，也不把相关、异常和预测混入基础质量诊断。

## 2. 角色契约

- `get_data_profile` 新增 `data.roles` capability，并把 Tool 版本从 `1.0.0` 升为 `1.1.0`；
  原有 `data.profile`、`data.quality` 继续由同一只读幂等调用返回，Planner 每次只选择用户请求中
  最具体的一项，避免重复读取数据集；
- `chatbi-data-roles-v1` 对每列返回 `time`、`metric`、`dimension`、`identifier` 或
  `unknown` 主角色、候选分数、稳定 Evidence code、profile 证据、置信度和 `ambiguous`；
- 推断只消费已治理 DataProfile 的列名、类型、空值率和基数，不读取额外原始行，不把模型输出
  当作角色真相；低置信、自由文本、常量或角色竞争会显式要求确认；
- MCP 输出 schema 固定完整嵌套结构并禁止角色/质量对象出现未知字段，使 Gateway 能在新任务
  建目录时发现远端 schema、版本或 capability 漂移；旧 TaskRun 仍按 6A 快照失败关闭。

## 3. 质量诊断与建议

- `chatbi-data-quality-v1` 当前覆盖整行重复、空值/全空列、常量列、非唯一标识字段和角色歧义；
- 每个问题固定 `issue_id`、code、severity、字段、画像 Evidence、建议动作和中文建议；
- 指标缺失不会建议静默填 0，时间缺失不会建议前后填充制造时间，ID 缺失不会建议生成伪 ID；
- 所有 Recommendation 均带 `automatic=false`，整体固定 `mutates_data=false`。工具不会创建衍生
  Dataset；后续若用户确认清洗，仍须通过受治理 `transform_dataset` 和现有血缘/权限边界执行。

## 4. Planner 与前端

- fast/template Planner 能区分 `data.profile`、`data.roles` 和 `data.quality`；同一请求同时出现
  画像、角色或质量词时只规划一次 `get_data_profile`；
- Profile Artifact 新增时间/指标/维度/ID 数量、待确认计数、字段角色标签和最多三条质量建议；
  卡片明确显示“仅建议，不自动修改数据”；
- 工具执行摘要改为行列数、指标/维度数量和质量问题数，不再把基础重复行数伪装为完整质量结论。

## 5. 6B-2 角色确认与下游门禁

- 趋势、异常、回归、相关和聚合请求复用现有 `waiting_user` 状态机；Host 产生
  `data_role_request`，候选列写入有界 `answer_schema.enum`，不允许 Planner 或模型改写
  确认范围；
- `answer_clarification` 在同一事务中校验候选列、计划版本、TaskRun 数据集绑定与当前
  `data_version_hash`，并把角色确认同时写入 `clarification.answered` 事件和 Checkpoint。
  记录包含确认 ID、列、角色、计划版本、TaskRun 状态版本与确认时间，进程重启后仍可恢复；
- 确认只对同一 TaskRun 数据版本生效。衍生数据集加入导致数据版本哈希变化后，旧确认不会
  被守卫采用；同一幂等回答不会重复产生确认；
- `trend_analysis`、`anomaly_detect`、`regression`、`correlation` 和
  `aggregate_preview` 在执行前检查已提供字段的时间/指标/维度角色。缺画像元数据、字段不存在、
  角色歧义未确认或角色不匹配均以稳定 code 留下拒绝 Observation，不创建 ToolInvocation，
  不占用工具预算；通过结果则写入 policy 审计摘要；
- 并行 ready frontier 发现角色门禁不通过时退回串行治理路径，确保拒绝事件可审计；通用
  `validate_role_requirements` 已冻结供后续 Join key 使用，但本切片没有新增 Join 工具，
  不宣称多数据集关联已实现。

## 6. 6B-3 匿名代表性评测

- `data_role_quality_eval_set.jsonl` 冻结 16 个领域中立的匿名 schema/画像场景，
  共 65 列，覆盖中英文时间、指标、维度、ID、自由文本、常量、全空、
  非唯一 ID、低基数数值和复合质量问题，不保存任何原始行或业务数值；
- 门禁固定 `role_accuracy >= 95%`、`ambiguity_recall = 100%`、
  `high_confidence_error_rate = 0` 和 `auto_mutation_violation_count = 0`，并对每个用例的
  quality issue code 做多重集精确比对；
- 当前基线为角色准确率 98.5%、歧义召回率 100%、错误高置信率 0、
  不自动修改违规数 0；唯一角色未命中为低置信且已要求确认，不构成静默错判；
- 首轮评测暴露并修复了英文 `*_code` ID、中文数值“等级/级别”维度和
  无语义提示低基数数值的歧义处理；低基数数值保留 metric 主候选但强制确认；
- CI 已接入 `data-role-quality` 强制门禁与脱敏 JSON 产物；报告只包含 case ID、
  计数、指标和集合 hash，不回显列名或 profile 元数据。

## 7. 6B-4 双传输与 Compose 恢复门禁

- 新增 `apps.api.data_role_recovery_probe`，在真实 Compose 共享 SQLite/Dataset Volume 上建立
  匿名固定数据集，并以生产 `AgentServiceRuntime` 的 reviewed descriptor 作为 Host 期望目录；
- 同一个 `get_data_profile` 依次经过生产处理器直接调用、官方 SDK stdio 和认证的
  Streamable HTTP，要求三个 `data-tools` 目录 hash、角色/质量结构化结果 hash 完全一致；
- 探针固定检查 Tool `1.1.0`、`data.profile/data.roles/data.quality` capability、只读幂等元数据、
  五类角色中的时间/指标/维度/ID 覆盖，以及重复行、常量列和全部 `automatic=false` 建议；
- Compose 门禁在首次等价调用后重启 `data-tools`，要求 Managed Gateway 建立至少第二代连接、
  重新执行严格目录发现，并在相同 Dataset 引用上得到相同结果；认证、目录或输出漂移失败关闭；
- `.data/e2e/data-role-recovery.jsonl` 的门禁报告只记录目录/结果 hash、版本、capability 和
  恢复代数，明确 `raw_data_in_report=false`，探针以 ERROR 日志级别运行，不主动回显列名、
  profile、样本行或业务值。
