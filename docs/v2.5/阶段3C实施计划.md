# v2.5 阶段 3C：受治理的指代消解

> 状态：3C-1–3C-3 本地实现完成；3B/3C 真实 Docker CI 仍待提交验证
> 更新日期：2026-07-30
> 前置条件：3A 已关闭；3B 本地实现收口，3C 不得绕过其容器恢复门禁

## 1. 目标

让后续请求中的“第二张图”“刚才的趋势”“这个数据集”和已确认实体，能够绑定到
当前主体、项目和对话内的确定对象，并在规划、执行、暂停和恢复期间保持同一个绑定。

解析由 Agent Host 完成，模型只能看到 Host 验证后的 opaque ID/hash 注解。解析器不读取
其他项目对象，不从上下文摘要推断数值事实，也不把模糊文本直接交给模型猜测。

## 2. 安全与一致性不变量

1. tenant、project、conversation 和主体只能由 Host 注入；
2. Artifact 只从当前对话读取，Dataset 只从当前项目读取；
3. 明确序号、时间选择器、唯一文件名和显式 ID 可以确定性解析；
4. 多候选、越界、伪造、删除或 hash 漂移均失败关闭，进入阻塞澄清或拒绝恢复；
5. Host 绑定随 TaskContract/TaskPlan 持久化，恢复时重新验证归属，不能按最新对象重猜；
6. 已验证绑定可以覆盖模型给出的报告 `analysis_ids` 或图表 `dataset_ref`；
7. 审计只记录状态、reason code、目标 ID、数量和 hash，不记录查询正文或 Artifact payload；
8. 指代绑定不是 Evidence，不能为数字、指标口径或知识结论背书。

## 3. 实施批次

### 3C-1：Artifact/Dataset 确定性解析

状态：本地实现完成并通过全量后端回归；容器发布证据归 3C-3。

- 建立当前作用域 Artifact/Dataset 目录和确定性 resolver；
- 支持序号、最近对象、唯一文件名及显式 `analysis_id`/`dataset_ref`；
- 多候选和越界生成现有 Planner 可持久化的阻塞澄清；
- 绑定写入 TaskContract/TaskPlan，Checkpoint 恢复重新校验；
- `gen_chart` 与 `generate_report` 服从已验证血缘；
- 冻结跨 tenant/project、篡改、删除和审计不泄密测试。

### 3C-2：已确认实体映射

状态：本地实现完成并通过全量后端回归；质量与容器发布证据归 3C-3。

- 只执行 Memory Policy 已接受、来源为 `user_confirmation` 的 `entity_mapping`、
  `field_alias` 和 `confirmed_decision`；
- 映射摘要必须严格符合 `memory-reference-v1` JSON，语义键由别名 hash 生成，并带
  作用域、版本、置信度、有效期及唯一项目内 Artifact/Dataset Link；
- Resolver 同时校验 TaskRun 固定 MemorySnapshot 和 live 生命周期；冲突、过期、
  未生效、删除、被取代、低置信度、目标丢失或跨项目映射均失败关闭；
- 歧义时只接受用户显式提供的 `memory_id` 作为当前 run 的一次性选择，并把版本/hash
  写入 `HOST_MEMORY_REF_V1` 计划假设；Checkpoint 恢复重新验证，不按最新映射重猜；
- 澄清和解析路径均不自动调用 `remember`、`revise` 或批准长期项目事实；
- Planner/Replanner 不能伪造、替换或删除 Host 绑定；图表和报告工具服从已验证
  Dataset/Artifact 血缘；
- 3D 仍负责用户查看、纠正、删除及相应前端/API 治理。

### 3C-3：质量与恢复门禁

状态：本地实现完成并通过全量后端与真实双传输探针；Compose CI 待验证。

- `coref_quality_eval_set.jsonl` 冻结 23 个领域中立对象/记忆引用场景，覆盖序号、
  最近对象、同名、多候选、删除、过期、版本漂移和跨项目/对话攻击；
- CI 强制运行质量集并上传只含状态/hash 的报告；确定解析率和应澄清召回率必须为
  100%，误绑定率和跨项目泄漏数必须为零；
- MCP 探针先由 Host 把对象引用和固定 MemorySnapshot 映射到同一个 Dataset，再验证
  直接调用、stdio 与 Streamable HTTP 的结果 hash、协议和错误语义等价；
- 联合恢复探针把 `HOST_COREF_V1` 与 `HOST_MEMORY_REF_V1` 写入不可变 TaskPlan；
  API 重启和 Compose 离线备份/恢复后重新验证 plan ID/version/hash、两个 resolution
  hash、暂停状态与目标 Artifact；
- 恢复探针要求原报告副作用恰好一次，探针 run 的工具调用数为零。

## 4. 非目标

- 不用模型摘要替代 Artifact、Dataset、Evidence 或 Memory 真相源；
- 不开放通用 `memory.write`；
- 不解析未经确认的业务指标公式或领域知识；这些属于阶段 5；
- 不在 3C 内完成用户记忆治理界面；这些属于 3D/阶段 4；
- 不因本地定向测试通过而跳过 3B/3C 的真实 Compose 门禁。

## 5. 退出条件

- 确定引用在规划、工具执行和恢复时保持同一目标；
- 模糊或越界引用不调用模型/工具猜测；
- 删除、篡改、跨项目和跨 tenant 引用全部失败关闭；
- 工具不能用模型参数替换 Host 已验证的单一血缘；
- 领域中立质量集、全量后端、迁移、浏览器和 Compose 恢复回归通过；
- 3B Docker CI 门禁已关闭，3C 实施记录和发布证据完整。
