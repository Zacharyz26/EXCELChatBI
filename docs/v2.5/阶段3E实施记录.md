# v2.5 阶段 3E 实施记录

> 状态：已完成；提交 `0b5980c` 的 backend、frontend 与 Docker/Compose CI 全绿
> 更新日期：2026-07-31

## 1. 本批交付

### SQLite v6 与不可变来源锚点

- `dataset_lineage_anchors` 保存 Dataset 最小身份、父引用和 tombstone；删除原始或派生
  Dataset 后不再因 `ON DELETE SET NULL` 丢失历史父链；
- `datasets.lineage_parent_ref` 和 `artifacts.lineage_dataset_ref` 固定创建时引用；
- 触发器自动记录、重命名同步和删除 tombstone，并拒绝伪造插入、身份改写、标签越界更新、
  tombstone 回退及已固定引用改写；
- v6 checksum 纳入启动校验；v3/v4/v5 升级回归和 v5 带 hash 备份迁移均已覆盖。

### 派生血缘图与 API

- `LineageStore` 直接读取 Dataset、Artifact、ToolInvocation、Evidence、Claim 和
  ClaimEvidence，不复制业务结果；
- 节点类型为 Dataset、Analysis、Artifact、Evidence、Claim；关系为派生、输入、产出、
  画像、汇入、形成证据和支持结论；
- 图使用规范排序生成稳定 SHA-256；支持 `max_nodes` 有界视图，同时返回完整图 hash/计数；
- 完整性检查覆盖跨 run、跨项目、锚点缺失/漂移和 Dataset 父链越界；
- 项目/tenant membership 和 conversation 边界失败关闭；审计与 API 均不输出工具参数、
  文件路径、数据样本、payload 或结果正文。

### React 血缘查看

- 工作区新增“数据血缘”入口；
- 五阶段列展示节点状态、引用短标识、入/出关系和完整性；
- 节点详情只渲染白名单元数据，并明确安全省略项；
- conversation API 虽可供后续页面使用，但当前 UI 以项目总图为默认，避免把完整性误解为
  单次对话局部结果。

### 质量、备份与恢复

- 新增 6 个领域中立冻结场景，`contract`、重复打开确定性、安全元数据、项目隔离、
  删除锚点保留和漂移检测六项指标均为 100%；
- CI 新增 `lineage_quality` 强制门禁及 `lineage-quality` 产物；
- 工作区备份计数补齐 TaskPlan/Step、Claim/ClaimEvidence 和 Dataset 锚点，manifest
  保存不含正文的全库 lineage hash；
- 联合恢复探针在 API 重启和离线破坏/恢复后比较项目图 hash、节点数和关系数；
- full-stack Playwright 在同一链路验证记忆治理、Excel 上传、profile 血缘和安全详情。
