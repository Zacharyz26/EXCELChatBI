## 3. 实际交付

### 3.1 SQLite v8 与不可变定义

- schema v8 新增 `domain_definitions` 和 `domain_field_mappings`；迁移 checksum、v7 备份升级、
  readiness 和受保护回滚路径已接入现有 migration runner；
- 定义包含语义键、正整数版本、公式、公式 hash、粒度、适用范围、负责人、来源、生效区间和
  opaque `chatbi://domain-definitions/{id}` Resource URI；URI 只暴露 32 位随机 ID，不编码项目、
  字段、来源或宿主机路径；
- 定义和字段映射均由数据库 trigger 保持不可变。旧报告可按 `definition_id`/`resource_uri`
  定位旧版本；新版本不能覆盖历史行；
- 发布接口使用 `Idempotency-Key`。同键同请求安全重放，同键异请求和同语义版本异内容均失败
  关闭；owner/editor 可写，viewer 只读，tenant/project 不匹配返回不可发现语义。

### 3.2 生效解析、冲突和公式编译

- `resolve` 按 UTC 生效时点返回 `resolved`、`conflict`、`expired` 或 `missing`；重叠区间保留
  所有候选，`definition=None` 且 `requires_clarification=true`，不按最高版本或创建时间选胜者；
- 阶段 5A 公式 DSL 只允许 `aggregate_preview`，参数只含受控概念键、`sum/mean/count`、排序
  和结果上限；自由 SQL、未知工具、多余参数和宿主机来源路径均被拒绝；
- Dataset 字段先登记到领域概念。编译器使用项目内映射生成带 `dataset_ref` 的白名单 Tool
  调用，并绑定 `definition_id`、语义版本和 `formula_hash`；映射缺失时不产生调用计划；
- 本批只支持可由现有 `aggregate_preview` 完整表达的分组聚合指标，不假装已经支持比率、窗口、
  跨表或任意表达式。

### 3.3 API、knowledge-tools 与 Evidence

- 新增项目级定义发布、版本列表、精确历史读取、生效解析、字段映射登记/读取 API；响应不暴露
  tenant、创建主体、幂等 hash 或数据库字段；
- `knowledge-tools` 新增 `domain_definition_lookup`，项目和主体来自签名 MCP RequestContext，
  不接受模型传入身份或 project 参数；提供 Dataset 时返回编译计划；
- Tool description 和返回定义继续按不可信资料处理。系统提示明确要求 conflict/映射缺失进入
  用户澄清，并禁止绕过 `compiled_invocation` 直接计算；
- 定义查询使用现有 `citations` Artifact 和工具成功落账路径进入 Evidence Ledger；Claim 提取器
  接受其显式 `source`，仍拒绝没有真实来源标签的知识结论。

## 4. 验证结果

- 新增领域仓储/MCP/冻结场景测试，覆盖版本、幂等、冲突、过期/缺失、历史定位、租户隔离、
  viewer 写拒绝、不可变 trigger、公式注入拒绝、字段冲突和受控调用编译；
- 新增 API 契约测试，覆盖 owner 发布、viewer 读取、跨租户不可发现、字段映射、编译和无胜者
  冲突响应；
- 新增 Claim/Evidence 与 Agent Artifact 测试，确保 `domain_definition_lookup` 与数据工具使用
  同一 Ledger，而不是形成第二套知识证据；
- 不依赖本机线程池的针对性回归：领域定义、冻结场景、SessionStore、Agent Tool 目录、五服务
  路由、Claim、迁移演练、CI/容器静态契约和治理控制共 **74 条通过**；`ruff` 和变更模块
  strict `mypy` 通过；
- 当前本机 AnyIO 线程门户异常：最小 FastAPI `TestClient` 和最小 `anyio.to_thread.run_sync`
  都会挂起，因此本批 HTTP/Agent 异步用例已实现但不能把本机挂起记为通过。需由后续干净 CI
  环境执行完整后端回归；这不等同于 Compose 门禁通过。
