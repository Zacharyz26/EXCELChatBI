# 阶段 6E 实施记录：多数据集关联与版本治理

> 状态：工程关闭；6E-1～6E-4 已通过远程完整 CI
> 更新日期：2026-08-14
> 前置：阶段 6D 已由提交 `3febd68` 的完整 CI 关闭

## 1. 阶段目标与切片

阶段 6E 在既有 TaskRun 固定数据版本、Host Policy、MCP Gateway/Server 和 Evidence Ledger
边界内增加多数据集能力。阶段继续坚持“模型规划 capability、确定性工具计算、Host 掌握授权
与状态”，不引入自由 SQL、纯 ReAct 自由循环或 Server 间递归调用。

1. **6E-1 Join 只读预检**：显式选择两个数据集和左右关联键，评估类型、匹配覆盖、基数关系、
   结果行数与膨胀风险；扩展所有数据集引用的授权和固定版本校验；
2. **6E-2 受治理 Join 执行与多父血缘**：在 6E-1 Evidence 和用户确认基础上执行固定 Join
   操作，新增多父 Dataset 版本/血缘真相表和可恢复原子提交；
3. **6E-3 Planner/React 协作**：展示两个输入版本、关联键、风险、确认状态、衍生数据集及完整
   多父血缘，失败或数据版本漂移时可解释地停止；
4. **6E-4 发布门禁**：冻结领域中立 Join 场景，验证跨项目、敏感键、多对多、行数膨胀、
   重启恢复、双传输等价及浏览器展示后再关闭阶段。

## 2. 6E-1 实际交付

- 新增 `dataset.join.preflight` / `join_preflight`，输入是封闭 JSON Schema：只接受两个 32 位
  opaque Dataset reference、左右键和 `inner/left/right/full` 枚举；没有 SQL、表达式、路径、
  自定义阈值或执行参数；
- DuckDB 只下推读取关联键统计，不返回原始键值或数据行，也不写 Dataset。严格输出契约固定
  `mutates_data=false`、`raw_rows_returned=false`，返回左右行数/空值/去重统计、匹配键数量、
  匹配行覆盖、匹配基数关系、确定性预估结果行数和膨胀比；
- 固定 500,000 行硬上限；不兼容类型、零匹配或越过上限直接 `blocked`。多对多、结果膨胀超过
  2 倍或任一侧键含空值返回 `requires_confirmation`，当前切片不会据此自动执行 Join；
- `MASK/EXCLUDE` 列禁止成为关联键；同一 Dataset 不能同时作为左右输入。基数关系仅依据实际
  匹配键计算，未匹配区域的重复值不会把一对一误判为多对多；
- 中央 Host Policy、独立 MCP Server 和 TaskRun 固定数据版本由只检查 `dataset_ref` 扩展为
  完整检查 `dataset_ref/left_dataset_ref/right_dataset_ref`。任一引用未登记、跨项目、格式非法
  或不属于任务冻结版本都会失败关闭；
- Planner capability 目录、确定性 Planner、LLM Planner 提示、中央 allowlist、`data-tools`
  服务目录和 Agent registry 已接入预检能力。多数据集请求必须明确恰好两个数据集、两侧键和
  Join 类型；Host 按已确认文本顺序固定左右 Dataset/键/Join 类型，不能由模型在 Tool Call
  中偷偷替换；
- 系统提示明确：`blocked` 必须停止；6E-2 交付前不得把预检写成 Join 已执行。

## 3. 6E-2 实际交付

- 新增 `dataset.join.execute` / `join_datasets`。输入复用 6E-1 的封闭参数对象，只接受两个
  Dataset reference、左右键与 `inner/left/right/full`，不接受 SQL、表达式、自定义输出路径、
  模型可控阈值或确认布尔值；
- Tool Contract 固定为 `read_only=false`、`idempotent=false`、`risk_level=high`。Planner 将执行
  步骤严格依赖预检 Evidence，Host 在执行前创建与 plan/step、契约 hash 和完整参数 hash
  绑定的 ApprovalRecord；MCP Gateway/Server 缺少完全匹配且已消费的授权时失败关闭；
- 执行前在工具内部重新运行同一预检。`blocked` 永不落盘；`ready/requires_confirmation` 仍受
  高风险审批约束。DuckDB 只执行固定等值 Join，并校验实际行数必须与预检的确定性预计一致；
  不一致时删除未登记输出并停止；
- 固定列投影保留左侧列，右侧重名列使用 `_right` 稳定后缀；`right/full` 在左右键同名时用
  确定性合并键保留右侧未匹配值。输出只返回 schema、行列摘要、新 Dataset reference、风险
  和双父 reference，不返回原始行；
- SQLite schema 升至 v11，新增不可变 `dataset_lineage_edges` 与
  `task_dataset_binding_parents`。旧单父血缘自动回填为 ordinal 0 主父边；Join 输出登记左右
  两条父边，血缘图、完整性 hash、工作区备份/恢复和删除引用计数均读取完整父集合；
- TaskRun 原子提交 Join Evidence 时校验两个父版本都属于冻结数据版本、结果锚点项目一致且
  SQLite 双父边完全匹配，再追加派生 Dataset binding；数据版本 hash v2 纳入有序父集合；
- Host 同时固定 `join_preflight` 与 `join_datasets` 的左右 Dataset、左右键和 Join 类型，模型
  不能在执行 Tool Call 中替换已确认参数。新结果继承两侧更严格的 sensitivity、列规则与
  小群体策略，避免通过 Join 派生数据集降级数据边界；
- 生产 Agent 工具目录由 16 个增至 17 个，`data-tools` 由 4 个增至 5 个；独立 MCP 服务、
  中央 allowlist、Compose 恢复目录和 Planner capability 已同步更新。

## 4. 6E-3 实际交付

- 新增 `chatbi-join-evidence-context-v1`。顺序或 ready-frontier 并行执行的 Join 预检都会把
  完整参数 hash、预检数据版本、左右输入版本/键、匹配关系、行数估计、膨胀比和风险写入
  Evidence source；投影固定 `raw_rows_returned=false`，不保存关联键值或数据行；
- Host 在创建或消费 `join_datasets` 授权前，必须命中完全相同参数的成功预检 Evidence，且
  预检 `data_version_hash` 必须仍等于当前 TaskRun 数据版本。缺少精确 Evidence 会返回可重规划
  Observation；预检已阻塞或数据版本漂移则把当前 Run 收敛到 `blocked`，不会创建授权或执行
  写入，也不会由模型自行解释成成功；
- TaskRun 详情 API 新增确定性 `chatbi-join-collaboration-v1` 投影。它只从持久 Invocation、
  Evidence、ApprovalRecord、TaskEvent、Dataset binding 和 SQLite 血缘边重建预检、等待授权、
  已批准待恢复、执行、完成、失败、阻塞和版本漂移状态；浏览器刷新不依赖内存中的模型轮次；
- React “多数据集 Join”区域展示两个 opaque 输入版本、左右关联键、Join 类型、基数关系、
  预计行数/膨胀比、全部风险、预检 Evidence、确认状态与版本一致性。Join 审批卡同步显示本次
  参数固定范围；批准仍只更新 ApprovalRecord，必须显式点击“继续执行”；
- 授权决定后前端立即重新读取服务端投影。有效 pending 授权阻止恢复；过期 pending 仅作为历史
  展示并允许恢复以重新申请，避免刷新后被失效授权永久卡住；Chromium 回归覆盖批准、刷新、
  恢复、消费授权和结果展示；
- Join 完成后显示衍生 Dataset reference、行数、左/右父版本及其 ordinal，并要求输出父集合、
  预期双输入和 SQLite 真相边完全一致才标记“完整双父血缘”。项目血缘 API/React 也公开安全的
  `ordinal/role` 元数据和父版本名称，不暴露参数正文、路径或数据样本。

## 5. 6E-4 实际交付

- 冻结 17 个领域中立 Join 生成器场景，覆盖 `inner/left/right/full`、一对一、一对多、
  多对一、多对多、单/双侧空键、类型不兼容、零匹配、500,000 行硬上限、`MASK/EXCLUDE`
  敏感键和同 Dataset 拒绝；其中 5 个场景真实物化 Join 并核对严格输出契约与有序双父结果；
- `join_quality_eval.py` 直接调用真实确定性预检/执行工具，强制预期结果、输出契约、
  风险分类、只读边界、失败关闭、执行契约和双父完整率全部为 100%，固定集合越界为 0；
  报告不保存键值、列名、行数、Dataset reference 或 Join 结果行，CI 强制上传
  `join-quality` 脱敏产物；
- 新增 `join_recovery_probe`。真实 Compose 门禁校验完整 `data-tools` 目录，证明进程内处理器、
  官方 SDK stdio 和 Streamable HTTP 的多对多/行数膨胀预检 hash 等价；同一探针还确认
  跨项目 Dataset、敏感键和缺失高风险授权均失败关闭，只有契约/参数 hash 完全绑定的
  授权才能经 HTTP 物化 12 行固定结果并通过双父契约；
- Compose 在探针检查点后真实重启 `data-tools`，要求 Gateway 连接代次递增、重新验证完整目录且
  恢复后预检结果 hash 不漂移；探针报告不包含原始数据、关联键值或 Dataset reference；
- Chromium 发布场景显式验收左/右输入版本与键、多对多、2.4 倍膨胀、全部风险、参数绑定授权、
  刷新恢复、显式继续、授权消费和完整双父血缘；服务探针只验证 MCP 边界，不替代 Host
  的 Profile、计划依赖、预检 Evidence、TaskRun 数据版本、ApprovalRecord 与 Verifier 控制。
