# 阶段 6：架构边界、前端性能与运维容量

> 状态：本地重构验收记录 · 日期：2026-10-10 · 不包含部署或发布承诺

本阶段只做行为保持型重构、前端拆包和可维护性门禁。数据库格式、SSE 事件、API 路由和
Artifact 格式没有变更；历史审批表继续存在，只移除了已经没有生产调用的运行时审批 API。

## 后端模块边界

### 编排领域下沉

以下纯领域模块从 `apps/orchestrator/control` 下沉到
`packages/orchestration`：

- `contracts.py`：任务契约和成功标准；
- `state.py`：Agent 状态转换；
- `task_plan_contract.py`：TaskPlan schema 与校验；
- `hypothesis_followup.py`：假设追问决策；
- `hypothesis_lifecycle.py`：假设执行生命周期。

旧路径保留显式 re-export 兼容层，避免现有集成方一次性迁移。生产代码和
`TaskStore` 使用新路径；`tests/test_architecture_boundaries.py` 解析 AST，阻止
`packages/**/*.py` 重新依赖 `apps.*`。

### AgentLoop 拆分

`apps/orchestrator/agent_loop.py` 从 5,496 行降到 5,278 行：

- `request_intent.py` 承担图表、报告、PDF 明示意图和图表维度覆盖判断；
- `artifacts.py` 承担工具结果到持久化 Artifact payload/file_ref 的投影；
- `tool_presentation.py` 承担工具参数的人类可读摘要；
- 调用方和测试改用公共模块，不再从 `agent_loop` 导入这些私有函数。

这次没有移动核心执行循环、事务提交顺序或重试状态机。后续继续拆分时，应以一次工具调用
从 reservation 到 Evidence/Artifact 原子提交为最小保护边界。

### TaskStore 收敛

`packages/session/task_store.py` 从 6,136 行降到 5,294 行：

- 删除没有生产调用的审批请求、查询、决定和消费运行时 API，以及仅为其服务的映射、重放
  和时间戳校验逻辑；
- 保留 v7 `approval_records`、`approval_operations` 表、迁移和备份恢复结构，用于旧
  数据库兼容；
- `task_hashing.py` 成为 Invocation 参数哈希和幂等键的公共归属，Agent、Join 协作和测试
  不再为哈希工具依赖整个 `task_store` 模块；
- `task_store` 显式 re-export 两个哈希函数，旧导入路径与新模块保持算法一致；
- SQLite 写事务、`BEGIN IMMEDIATE`、state_version 乐观并发和 checkpoint 行为未改变。

历史 RequestContext 审批字段仍按数据库/协议兼容字段保留，但当前 Agent 不生成审批事件或
审批记录。若未来重新引入审批，必须设计新的公开契约和迁移，不能直接复活已删除的旧方法。
历史手工操作或旧测试可能留下 paused 审批记录，但当前没有审批路由或生产决定/消费入口，
因此这些运行不能继续批准；它们只能通过通用取消路径终止。保留审批表、迁移和备份仅表示
数据格式可读取，不表示旧审批工作流仍可继续执行。

## 前端拆包与可访问性

基线生产构建只有一个 1,434.11 kB（gzip 467.42 kB）入口 JS。重构后：

| chunk | 原始大小 | gzip | 加载时机 |
|---|---:|---:|---|
| 主入口 | 365.34 kB | 114.34 kB | 首屏 |
| EChartsRenderer | 510.97 kB | 171.87 kB | 出现图表 Artifact 时 |
| AgentControlPanel | 22.19 kB | 7.21 kB | 打开任务协作面板时 |
| MemoryGovernancePanel | 5.98 kB | 2.65 kB | 打开记忆治理面板时 |
| LineagePanel | 5.99 kB | 2.66 kB | 打开血缘面板时 |

主入口原始体积下降 74.5%，gzip 下降 75.5%。ECharts 使用
`echarts/core`，只注册 line/bar/pie/scatter、Canvas、Title、Tooltip 和 Grid；这与当前
后端 chart schema 一致。ECharts 异步 chunk 仍高于 Vite 默认 500 kB 警告线 10.97 kB，
但不影响首屏。后续若增加图型或 ECharts 组件，必须同步更新注册表和浏览器回归。

所有懒加载边界提供 `role="status"` 加载提示；图表容器提供 `role="img"` 和稳定的可访问
名称，名称由图标题、系列名和稳定 chart id 组成，可区分同页多图。每个图表和按需面板均有
局部 ErrorBoundary，失败不会清空聊天正文或已加载区域；根入口边界只作为最后兜底。

浏览器会缓存 React.lazy 的 rejected promise，因此关闭再打开面板不是恢复手段。错误回退明确
提供“刷新并重试”，用新文档重新获取当前部署的入口和 chunk；按钮旁提示未发送草稿和面板
临时输入会丢失，真正刷新前还需用户确认。Playwright 已注入一次 EChartsRenderer chunk
网络失败，验证聊天正文保留、取消刷新时草稿保持，以及确认后刷新恢复。三个面板共用同一
错误边界并通过构建和正常浏览器回归，但尚未分别注入每个面板的独立网络失败，这是当前门禁
覆盖限制。

## 运维与容量边界

当前默认配置是工程保护值，不是生产容量承诺：

| 项目 | 默认值 | 说明 |
|---|---:|---|
| 单次上传 | 50 MB | 另有 multipart envelope 限制 |
| 单次 Agent 并行工具 | 4 | 配置范围 1–16 |
| 对话历史 | 20 条 | 进入 Agent 上下文的默认窗口 |
| RAG 并发查询 | 2 | 还受队列和独立服务超时约束 |
| 知识库文件数 | 1,000 | 单项目配置上限 |

系统仍定位为单 API worker、单实例 SQLite 的技术预览。SQLite 适合当前单机事务一致性验证，
不宣称多副本写入、企业多租户或水平扩容就绪。扩容前至少需要外部事务数据库、跨进程运行
租约/事件广播、对象存储和独立容量压测。

运维观察重点：

1. 监控 SSE 活跃订阅、RunControl 活跃 run、工具 unknown 状态和延迟清理失败；
2. 对 SQLite 锁等待、WAL/备份增长、Artifact/Report 磁盘占用设置告警；
3. 修改并发参数时同时验证模型费用、MCP 连接池、RAG 队列和取消传播；
4. 前端发布比较入口与异步 chunk，避免把 ECharts 或面板重新静态引入。

## 依赖与安全检查

- `uv lock --check --offline` 通过：Python 锁文件可在本地缓存中解析；
- 前端 TypeScript + Vite 生产构建通过；
- 当前环境没有全局 pnpm，仓库也没有 npm lockfile，因此
  `npm audit --offline --omit=dev` 以 `ENOLOCK` 退出。没有生成 package-lock，也没有
  安装或更新依赖；本阶段不能据此宣称 JavaScript 依赖无已知漏洞；
- 后续 CI 应在 pnpm 可用且允许访问审计源的隔离环境运行
  `pnpm audit --prod --audit-level high`，并保存审计时间和数据库来源。

完整 BGE 权重链路、GPU 等价性、付费模型和真实业务数据没有在本阶段验证，仍按阶段 5 文档
列为未授权/未覆盖范围。
