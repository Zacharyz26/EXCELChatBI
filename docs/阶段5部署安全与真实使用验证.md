## 安全与部署改动

### 上传边界

- `MAX_UPLOAD_MB` 同时注入 API 与 Web，默认 50 MiB；
- API 在 Starlette 解析 multipart 前检查 `Content-Length`，并对缺失长度/分块请求累计原始
  ASGI body；包络上限是 `MAX_UPLOAD_MB + UPLOAD_MULTIPART_OVERHEAD_MB`；
- Web 入口脚本以相同两项计算 `MAX_UPLOAD_BODY_MB`，Nginx 据此限制整体请求体；
- 代理层 413 返回与 API 一致的 JSON：
  `{"detail":"文件过大（上限 50 MB）"}`；
- UploadFile 写盘仍按 `MAX_UPLOAD_MB` 限制文件本身，超过时清理半成品；
- 配置范围固定为 1–1024 MiB，避免零值或异常大值。

默认 multipart 包络余量是 1 MiB（允许配置 1–16 MiB）。解析前回归覆盖伪造超大
`Content-Length`、无长度分块请求和恰好等于文件上限三条边界。真实 Nginx 代理 413
仍需 Docker daemon 可用后执行，不能用静态模板测试替代。

### 凭据与启动

- 根 Compose 不再提供可预测的 Bearer token 或 MCP secret 默认值；
- API 生产模式只接受 `AUTH_TOKENS_FILE`；根 Compose 的 MCP token/HMAC 也只挂载
  Docker secret 文件。直接运行独立 MCP 进程仍兼容互斥的直接环境值或文件；
- 仓库已移除六个 `deploy/secrets/*.dev` 运行时凭据文件；
- `.gitignore` 和 `.dockerignore` 排除运行时 secret；
- 本地/CI Compose 检查使用 `scripts/compose_test_env.sh` 在临时目录生成合成凭据，
  退出时精确删除；
- `scripts/scan_tracked_secrets.py` 在提交前扫描已跟踪与未忽略的新文件，并在 CI 中扫描
  checkout；规则覆盖敏感文件名、私钥头和常见云/代码托管/模型供应商 token 形态。
  输出只包含路径、行号和规则，不输出疑似秘密值。

生产启动前必须创建独立 secret 文件并显式传入所有 `*_FILE_PATH`。不得把临时合成凭据、
示例值或 secret 文件提交到 Git。

## RAG 容量与资源结果

### 保护措施

- `HybridRetriever` 同时限制执行槽与 `RAG_MAX_QUEUED_QUERIES` 等待槽；队列满时立即拒绝，
  等待超过
  `RAG_QUERY_QUEUE_TIMEOUT_SECONDS` 时明确拒绝，不形成无界队列；
- 查询长度由 `RAG_MAX_QUERY_CHARS` 限制，`top_k` 固定为 1–10；
- CPU profile 默认最大并发/等待各 1，GPU profile 默认最大并发/等待各 2；API 与独立
  knowledge-tools 使用同一配置；
- `scripts/kb_load_test.py` 限制最多 1000 个请求、32 并发、10 个 warmup；
- `scripts/rag_resource_probe.py` 限制最多 5000 合成片段、1000 请求、8 并发和
  1024 维，并且只在系统临时目录创建 Milvus Lite 数据库。

MCP SDK 使用 `abandon_on_cancel=True` 时，只能让异步调用方停止等待，不能安全强杀已经进入
底层的同步检索线程；槽位会保留到该线程返回。队列上限避免取消后无限堆积，但下游
Milvus/模型仍必须配置自身超时，不能承诺同步依赖永久挂起后自动恢复容量。
