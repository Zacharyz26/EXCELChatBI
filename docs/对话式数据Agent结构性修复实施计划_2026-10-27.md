## 1. 目的与范围

本计划处理阶段 2 真实业务主链暴露出的同一类跨层结构问题：请求意图、工具执行、数据版本、事实 Evidence、回答验证、展示和恢复之间缺少一致契约，造成正确事实误拒、错误事实放行、计划与意图不一致以及合法澄清无法完成。

这是现有模块内的局部结构性修复，不是：

- 对原始失败措辞堆特例；
- 放宽 verifier 或跳过版本、范围、字段和单位守卫；
- 新建第二套事实数据库；
- 引入 LLM Planner；
- 重写 Agent、计算内核、图表或 PDF；
- 新增自由 SQL、RAG 或其他产品能力；
- 承诺解决任意自然语言、复杂 OR、多语言或所有未知单位。

原准备方案 A/B/C/D/E 在本计划中分别改名为 R1/R2/R3/R4/V1，避免与旧 A–G 交付清单混淆。四批修复和一批验证均属于六阶段总纲的阶段 2，不是另一套总计划，也不是五次部署。

## 2. 已确认问题与设计基线

冻结基线：`375129ff5a97ea44019d61b67d735686fdc4ff67`，包含预算修复 `4f2bb185ac4f6164e31acaf62fc32857fe9cb8dd`。2026-10-27 文档落库前实时分支/HEAD 与归档一致，编辑前工作树、索引均为空；本次只有文档改动。每批实施前仍必须重新核对 HEAD、工作树、索引、未跟踪文件和并发写入，不能退回 `816e6fb…` 而丢失后续修复。

五类共同根因：

1. **事实角色、时点和版本绑定不完整**：例如筛选前 75、筛选后 38 被交换后仍可能由同值 Evidence 放行。
2. **数量发现与文本结构分叉**：中文“七/八个月份”可能未被提取，完整 verifier 只验证剩余正确数字后错误通过；Markdown、列表、metadata 又会误拒正确事实。
3. **任务义务被多套规则重解释**：清洗/去重请求、分组和指标在计划、执行和完成验证中不一致。
4. **能力、澄清和前端选项不同源**：工具支持月份分组，但前置枚举或前端候选可能无法表达合法答案。
5. **上下文、交付和停止来源投影不清**：active dataset、last profile、Artifact、恢复状态及诊断停止原因可能混淆。

独立复审的关键反例：

- “筛选后 75，筛选前 38”等前后互换错误，完整 verifier 曾错误通过。
- 粗体标签和引号确认下的前后互换也可能错误通过。
- “覆盖八个月份”加正确总计 1350 时，中文数量未被提取，完整 verifier 错误通过。
- “覆盖六个月份”虽然结果正确，但漏提取仍是覆盖缺陷，不能因最终 PASS 忽略。
- 阿拉伯数字 8 个月应拒绝、6 个月应接受；普通“七号方案”不得被误识别为数量事实。
- 常量频道字段仍可能需要合法角色确认；不得为了让旧 F11 变绿而取消保守守卫。

## 3. 必须保留的既有安全边界

- Dataset 不可变、TaskStore 原子工具提交、Invocation/Evidence/Artifact/Checkpoint 的版本和哈希关系。
- `dataset_scope.verified_analysis_scope` 和 Host lineage proof 对合法数据版本与范围的决定权；文本不能创造范围。
- Evidence `result_hash`、有界 `summary.value_index` 和 Claim `value_refs` 的可审计关系。
- 报告实际 Markdown/PDF/source hashes 和 `total_deliveries`，不得简化为“文件存在”。
- AND 筛选合同；无法表达 OR 时明确澄清，不静默拆成 AND。
- 字段、root、版本、filter、group、unit、denominator、count basis 和时间点守卫。
- unknown usage 不等于 0；预算保守预留、幂等、取消、unknown 工具结果不自动重试。
- required 步骤不能通过删除 pending、删掉声明或标记 completed 来绕过。
- 旧记录不可重写成新 schema；旧代码不理解新记录时只读或阻塞，不能回到已知不安全 fallback。

## 4. 目标契约

### 4.1 任务契约

在现有 `TaskContract`/`TaskPlan`/`AnalysisRequirements` 上扩展，不建第二个 Planner。每轮请求固定 message id、source hash、contract schema version 和 parent/clarification revision。

operation obligation 至少表达：action、object、current/prohibited/deferred/described/absent 意图、原文 span、输入数据绑定、依赖顺序、filters、group_by/grain、measures、total 和输出交付项。

同一 typed 结果必须驱动计划、工具准入、完成条件和澄清。解析不唯一时等待用户，不从最终回答倒推授权。

### 4.2 事实契约

Fact locator 由 `evidence_id + result_hash + source_path + invocation_id + role + binding` 组成。事实投影只能在可信工具成功事务内，由 Host 从真实 result 生成并冻结 producer/schema/source path/projection hash。

现有库不保证长期保存完整原始 result；后验只能重算已持久投影并交叉比较已存 hash。source path 缺失或被截断时保持 unknown，旧记录不因新 schema 自动获得认证。

Binding 应包含项目/会话权限、dataset ref、root/parents、不可变版本或调用 branch hash、scope proof、完整字段名、statistic、count basis、group/grain、unit、denominator 和 semantic timepoint。

调用的 branch binding hash 是绑定集合哈希，不是数据文件哈希；不能用最终 run hash 替换先前 invocation 的版本。字段在版本内用完整列名定位，rename/join 必须携带父列映射，不凭同名借证。空值数、非空数、缺失率绑定同字段/版本/分母；舍入沿用现有精度规则，不扩大容差。未知单位保持完整字段名；现有 42 项单位白名单只是有限兼容边界，不代表通用单位体系。

### 4.3 展示和交付契约

回答、表格、图表和报告消费同一组已验证事实引用。自然语言解释可以自由，但所有数值、身份、范围和时点声明必须绑定 Fact locator；残余肯定事实未绑定时必须拒绝、澄清或明确未交付。

共享文本视图保留原文 span 和 offset mapping，区分标题、列表、表格、inline/fenced code、引号、疑问和否定。格式规范化不得吞掉真声明。

图表、表格和 PDF 必须对齐 dataset、filters、group/grain、measure/aggregation、unit、null policy 和截断政策。下载 hash 只证明传输，还需核对页面内容。

当前图表按 dataset/encoding 独立重聚合，不假定直接消费月表；还须比较日期顺序、分组最小规模与截断政策，不能仅凭总和相等判一致。选中多个图必须全部交付。保留所选 analysis 集合、source hash、实际 Markdown 片段和 PDF 字节 hash、`total_deliveries` 证明；不另建可编辑的事实真相源。

### 4.4 上下文与恢复契约

数据变换后原版本不变，子版本成为新授权执行上下文；历史事实仍属于旧版本。active dataset 与 last profile 分开记录。重开从持久化合同和不可变引用恢复，不从历史自然语言重建事实。

澄清答案绑定 question id、plan version、run state version 和 dataset binding，不能修改其他义务。合法后端选项必须可由前端表达并被后端接受。

多个候选执行版本不唯一时先澄清；失效引用、文件缺失、权限或版本不符应标记阻塞/不可用，不得重置为 completed。失败 run 已产生 child 时，后轮采用哪个版本仍须明确策略并测试，不能只凭旧画像侧栏推断计算已经错源。

### 4.5 不确定性与失败处置

- 任务绑定歧义：`WAITING_USER`，给出可回答的问题；无合法候选时提供安全更正路径。
- 错字段、数值、角色、版本、范围或无来源声明：拒绝/`NEEDS_ACTION`，不以宽松匹配补齐。
- 合法工具失败：保存 failed/unknown Observation，不用无关工具成功掩盖；遵循原幂等、预算和重试约束。
- required 交付不能完成：`BLOCKED`；可选项降级明确未交付，不能删除 required 条件换取 completed。
- missing/null/非法 usage：费用 unknown，保留全额保守承诺并 halt；网络请求结束不代表可释放财务预留。合法零值按完整 usage 处理，未知转已知不擅自自动对账。
- 诊断守卫停止与供应商额度耗尽、正式预算 halt 分开记录，不改变预算异常的阻断等级。
