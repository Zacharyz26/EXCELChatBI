## 2. 后台 run 生命周期

- `/chat/stream` 创建由 `AgentRunManager` 持有的后台 producer，SSE 连接只是有界生命周期
  的订阅；客户端收到 `done(waiting_user|paused)` 或主动断开时不会关闭 producer；
- 同一 run 可在恢复/回答接口建立新订阅，producer 在模型轮次前后、工具调用前和工具提交前
  检查 cooperative pause/cancel 边界；
- 托管 run 继续执行总时限：模型/工具操作按剩余 active-time 截断，paused 与 waiting_user
  的等待时间不消耗执行预算；
- API 关闭时先把没有活动工具调用的 running run 持久化为 `paused + Checkpoint`，再取消
  进程内协程；waiting_user/paused 不会被关闭流程错误改成 cancelled；
- 工具调用正在执行或已有 unknown Invocation 时不能 pause；取消、超时或进程丢失无法
  确认副作用时，Invocation 记为 `unknown`、步骤记为 blocked，Verifier 禁止完成和自动重试。

## 3. 控制协议与安全

已实现：

```text
POST /agent/runs/{run_id}/pause
POST /agent/runs/{run_id}/resume/stream
POST /agent/runs/{run_id}/cancel
POST /agent/runs/{run_id}/clarifications/{question_id}/answer/stream
POST /agent/runs/{run_id}/steps/{step_id}/retry/stream
```

- 所有写接口重新校验项目 owner/editor 权限；不可见资源统一 404；
- 所有命令要求 `Idempotency-Key` 和 `If-Match`，命令 hash 与生命周期事件同事务保存；
  同键同请求只返回已提交事件，同键不同请求 409；
- 控制结果以数据库提交为真相源；pause 先关闭新的执行边界、提交失败即恢复信号，
  resume/cancel/澄清回答和步骤重试则在持久化成功后唤醒或终止运行宿主；
- 澄清回答校验 question ID、随机 resume token、有界 JSON answer 和当前状态；token 不能
  替代认证，回答只消费一次并作为用户消息持久化；
- 用户步骤重试只接受 paused 任务中的 failed/blocked 步骤，生成不可变计划新版本；
  已 completed/skipped 步骤及其 Invocation/Evidence/Artifact 保持不变。

## 4. Checkpoint 恢复

- pause、waiting_user、工具成功和步骤重试都形成持久 Checkpoint；Checkpoint 记录
  state/plan version、最后事件序号和当前计划已完成步骤集合；
- 恢复前验证 Checkpoint 属于当前 run、计划版本匹配、事件游标不越界、已完成步骤与数据库
  一致，并拒绝 running/unknown Invocation；
- 执行宿主丢失时，从 SQLite 恢复 TaskContract、活动 TaskPlan/TaskStep、对话上下文和预算，
  在原 `run_id` 上重新进入 Executor；调度器只开放 pending 且依赖已完成的步骤；
- waiting_user 的宿主丢失后，回答接口会从持久化问题和 Checkpoint 生成 plan revision，
  再继续原 run；
- 启动扫描把无活动 Invocation 的旧 running run 转为 paused；有活动 Invocation、
  planning 或 verifying 的不安全状态仍失败关闭。
