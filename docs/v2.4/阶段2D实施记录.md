## 2. 规范执行路径

- `AgentToolRegistry.execute_mcp` 是 Agent 循环的规范执行入口；`_execute_tool` 不再对真实
  Registry 调 `registry.execute`。旧同步入口只保留给迁移兼容和聚焦单元测试；
- Gateway 在每代连接上完成官方 SDK `initialize` 和 `tools/list`，并校验固定协议版本、
  静态 allowlist、完整契约 hash、输入 schema 和输出 schema；目录或 schema 漂移失败关闭；
- Host 在策略允许并原子创建 ToolInvocation 后构造 `MCPRequestContext`。主体、项目、对话、
  run、计划版本、步骤、Invocation、幂等键、权限快照、trace 和 deadline 都来自受控状态，
  不进入模型可填写的 tool arguments；跨进程上下文使用独立 HMAC key 签名，Server 在执行
  前校验，篡改或缺失签名返回 `invalid_context_signature`；
- 成功调用的 Evidence 记录真实 transport、是否降级、Gateway 健康状态/连接代次和 MCP
  Contract/Artifact 后置条件校验结果；SSE `tool_end` 同步暴露 transport 与 degraded；
- TaskRun 结束、暂停退出、取消或异常时关闭所属 MCP session/stdio 子进程，恢复原 run 时创建
  新连接并重新发现工具。

## 3. 超时、断线、取消和健康

- 连接和调用均受硬超时约束。连接超时返回可恢复的 `mcp_connect_timeout`；已经进入
  `tools/call` 后超时返回 `mcp_call_timeout + result_unknown`，Invocation 转为 unknown，
  run 进入 blocked，禁止自动重试；
- 客户端任务取消会取消官方 SDK 调用并使当前 session unhealthy；下次调用重新
  `initialize + tools/list`，不复用状态不明的 session；
- 仅契约同时声明 `read_only=true`、`idempotent=true` 的调用允许在传输断线后按
  `AGENT_MCP_MAX_RECONNECTS` 使用原幂等键有限重连。写入/副作用调用断线后不重放；
- 健康状态分为 `cold/healthy/degraded/unhealthy/closed`，同时记录 generation、
  consecutive failures 和稳定错误码。健康不替代工具发现；
- 认证失败、协议不兼容、工具目录/schema 漂移和策略拒绝不进入重连或降级路径。

## 4. 受控兼容与部署约束

`AGENT_MCP_TRANSPORT` 支持：

- `in_process`：迁移兼容和测试；
- `stdio`：本地标准协议执行，命令使用 JSON 字符串数组解析，不经过 shell；
- `streamable_http`：容器/部署路径，必须提供 URL 和服务 token。

`AGENT_MCP_ALLOW_IN_PROCESS_FALLBACK` 默认为 false。显式开启时，也只允许“尚未进入
tools/call 的连接失败 + 只读幂等工具”降级；认证、契约漂移、调用中断和副作用工具永不
降级。`staging/production` 启动配置强制 Streamable HTTP、Bearer API 认证和非空服务
token、上下文签名 key，并禁止进程内 fallback。

当前 2D Client 配置面向一个暴露本次 Agent 完整 allowlist 的逻辑工具端点。阶段 2E 将把
该逻辑端点拆到 `data/stats/chart/report/knowledge` 服务目录并完成 Compose 网络、readiness、
持久卷和容器重启验证；2D 不提前声称这些部署产物已经完成。
