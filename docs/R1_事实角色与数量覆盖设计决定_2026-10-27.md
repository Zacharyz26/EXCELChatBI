## 1. 删除差量由确定性工具产生

`transform_dataset` 继续按排除行、AND 筛选、去空、去重、排序顺序执行。增加版本化 `row_changes`：整次 removed_count，以及每个实际执行步骤的 operation、rows_before、rows_after、removed_count、count_basis 和列范围。去重差量是按 keep-first 删除的多余行，不等于参与重复行或组数；整行与指定列去重分别记录。排序的合法差量为 0。组合变换的整体差量不得借给单步。

单源输出合同在 `mcp_servers/common/catalog.py`；步骤结构闭合且计数为非负整数。binder 只读取工具明确返回的差量，不能相减补造。旧输出无差量保持不支持。

## 2. Evidence 投影和迁移

复用 `Evidence.summary.value_index`，不增加事实数据库。新增版本化 fact_projection envelope；数值只在索引中保留一份。可信生成点为 `TaskStore.commit_tool_success`：从实际完整 result 和持久 Invocation 生成，不能给调用方传来的任意索引盖章。绑定 producer、schema、run/invocation、result_hash、调用 branch hash、input/output ref、操作与计数口径，并封存 projection hash。branch hash 是调用时绑定集合，不能用最终 run hash 或 parquet hash代替。

本批迁移 transform 行数/差量及 aggregate 的分组计数；其他既有 profile/stats/chart 语义仍走原有严格绑定，不宣称已迁移全部事实。新投影存在就严格验证；未知版本、损坏或缺源不降级。旧明确 rows_before/rows_after 仅按 legacy 角色保守读取，不认证为新投影、不生成 delta。最终 Verifier 必须检查投影对应当前 run 成功 Invocation 的 tool/id/result hash 与绑定；不能信任传入的 Claim supported 标记。

投影具体字段：`schema=operation-count-facts-v1`、`producer`、`run_id`、`invocation_id`、`result_hash`、`branch_hash`、`input_ref`、`output_ref`、`columns`、`step_count`、`arguments`、`invalid`、`count_state`、`paths`、`projection_hash`。每个 `value_index` 事实含原 `path/value/source_kind` 与 `fact={role, operation, basis, columns, step}`。哈希输入是去掉自身 hash 的 envelope 与按 paths 顺序选出的 facts，UTF-8 JSON、排序键、紧凑分隔符。上下文副本必须与封存 arguments/branch 完全相等；消费者不接受在未封存 numeric_context 中另加参数。

兼容决定：部分旧聚合结果具备可验证度量但缺少分组数量的完整元数据时，封存 `count_state=unavailable`、空 paths，并移除调用方原 `$.group_total`，不推导分组数。这个已知 schema 状态不等于坏投影降级；已有度量仍用旧严格绑定，数量声明仍拒绝。显式 null/非法计数、元数据冲突、预览行数与 truncated 矛盾均为 invalid。只有 aggregate 的 unavailable 可以空 paths；transform/available 不可以。真实 MCP 聚合输出仍受原完整输出 schema 约束。

分步和整次事实不能同值互借：封存时校验首末计数、每步连续性、每步及整次差量、basis/columns 和排序零差量；这只是核对工具输出，不在 binder 里生成差量。中间步骤没有实际 DatasetRef，不能冒称初始或最终版本。未指明阶段的剩余/删除数量只读整次事实；通用清洗后/输出量仅从已封存变换血缘的终端数据选择，多个无从区分的终端继续拒绝。精确的筛选、去空、去重操作仍绑定对应步骤。

## 3. 中文数量与未知处理

不扩大底层十进制解析器，不全文替换中文数字。统一保留候选的原 token/span；新增严格中文非负整数计数读取，先按数量对象/角色绑定，再比较值。支持 0–999999999999 范围内常用零至九、两、十百千万亿的规范整数结构；近似、分数、比例、倍数、未知数量或无法唯一解释的写法保留 unknown，不能通过未提取而放行。

数量发现不依赖 Evidence 中是否恰有同值，也不扩充“月份”对象白名单。利用有界数量结构和现有字段/分组身份；未知业务对象也必须留下未支持声明。编号标签、字段名、说明性枚举保持非事实。已有中文比例、重复口径未支持测试的 token/span/unknown 分类保留。

候选发现改为数量—量词—相邻对象，量词复用固定词典的词性（行/列/组保留记录结构义，号作为编号标记）；不靠“共有/包含”等动词发现，后一个数量不会被前一个对象吞并。数值覆盖保留最大表达，包括中文小数和分数；不支持的表达不能截取尾部整数。当前代码仍有按词法标记 document_reference 的旧路径，这不是可核验的数量用途证明，其退出与兼容策略见新裁决。直接交付请求的 requested_output 不等于实际交付；肯定交付数量仍须逐一核对当前调用、Evidence 和真实 Artifact。不能用“请”整句豁免或用计划要求数作交付数。

范围比较复用 `analysis_requirements` 的 AND、引号与字面值语法；R1 展示侧允许自然等号、已知完整字段及引号字段，未知比较条件保留为拒绝。任务编译默认语法保持不变，不借此实施 R2 的澄清或计划变化。

R1 仅整理数量和操作角色的局部 span/赋值边界，冒号不是丢弃 owner 的分句符；完整 Markdown/段落统一仍属于 R3。
